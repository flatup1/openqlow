# 設計（なぜこうしたのか）

判断の基準は最後まで1つだけです: **大会を止めないか。**

---

## 1. イベントステートを唯一の真実にした

画面が5つあると、普通は「画面Aが画面Bに知らせる」形になります。これは必ず壊れます。
1台でも取りこぼした瞬間に、画面ごとに違うことを言い始めるからです。

そこで、**状態を持つ場所を1か所（Durable Object `EventRoom`）に固定**しました。

- 「次へ」「停止」「再開」は、すべて **その1か所を書き換えるだけ**
- 5画面は **その1か所を見ているだけ**（画面同士は一切通信しない）
- どの画面も、状態から**計算しているだけ**なので、遅れて繋いでも必ず同じになる

書き換えの規則は `core/state.ts` の純関数 `reduce()` にすべて入っています。
ネットワークも時計も触らないので、オフラインで全部テストできます（63件）。

---

## 2. タイマーは「残り秒」を保存しない

保存すると必ずズレます（誰の時計を信じるか問題が出る）。

保存するのは **開始時刻（サーバー時刻）と積算だけ**。残りは各画面がその場で引き算します。

```
残り = 目標時間 − (積算 + (今 − 開始時刻))
```

これで、

- 再読み込みしても同じ値が出る
- 90秒遅れて繋いだ端末も、いきなり正しい残り時間から始まる
- 停止中は積算が増えないので、**5分止めても1msも減らない**

各端末は `/api/time` で往復時間の半分を使ってサーバー時計とのズレを測り、60秒ごとに測り直します。
実測で3端末の到達差は 11〜12ms でした。

---

## 3. 権限は「入口」ではなく「サーバー」で切った

MC画面・表示画面にボタンを置かないのは**親切**であって、**保証**ではありません。
保証は Worker 側にあります。

- 書き込み口（`/api/command` `/api/undo` `/api/program/*` `/api/music/check`）は**操作キー必須**
- WebSocket は**配信専用**。そこから状態を書き換える経路が存在しない
- キーの比較は長さを見てから定数時間で行う

だから、MC の端末で開発者ツールを開いても、大会は止められません。

---

## 4. 「元に戻す」は1手だけ

何手も戻せると、本番で「どこまで戻したか分からない」という、より悪い事故が起きます。
v1 は**直前の一手だけ**。しかも、戻したときも `version` は前に進めます
（画面側の「新しい方を採用する」判定を壊さないため）。

---

## 5. 音源は色でしか語らない

Apple Music を第一優先、YouTube を第二優先。判定は `core/music.ts` の純関数です。

- 緑 = Apple で再生できる
- 黄 = YouTube だけ／尺が未設定（**進めてよい**）
- 赤 = URLが無い・形が違う・**リンク切れを検出した**

大事な一点: **確認できなかったリンクは赤にしません。**
当日の通信不良や 403 で赤が増えると、運用ルール（赤ゼロで開始）が信用されなくなり、
最後は誰も見なくなるからです。赤は「本当に直すべきもの」だけに残します。

---

## 6. 画面を静的書き出しにした

Next.js は `output: 'export'` で静的HTMLにしています。
サーバーサイドレンダリングが落ちて画面が真っ白になる、という壊れ方を最初から消すためです。
状態は全部 Worker 側にあるので、画面は静的で足ります。

さらに、接続先は URL の `?api=` で上書きできます。
**大会当日にビルドし直さないと直せない状態を作らない**ための逃げ道です。

---

## 7. 壊れたときに「止まらない」ようにした場所

| 壊れるもの | どうなるか |
|---|---|
| WebSocket が切れる | 800ms のポーリングに自動で切り替わる。復帰したら自動で戻る |
| ネットワークが完全に切れる | 最後の状態を出したまま「未接続」と赤く出る。**画面は消えない** |
| Google スプレッドシートが落ちる | 取り込みだけ失敗する。**今の番組表はそのまま**。CSV手貼りの口もある |
| 音源リンクの確認が失敗する | 「未確認」にする。赤を増やさない |
| 壊れた行が番組表にある | その行だけ捨てて、注意書きに出す。取り込み自体は成功する |
| 誤ったコマンドが飛ぶ | 例外を投げずに拒否して、状態は1msも変えない |
| 停止中に「次へ」を押す | 拒否する（先に再開させる） |

---

## 8. Version 2 以降に回したもの（v1では作らない）

- AI実況
- DJ自動化 / Apple Music 自動再生（v1 は**人が押す**。システムは音を鳴らさない）
- OBS連携 / 配信テロップ出し
- 勝敗の記録・トーナメント表の自動更新
- 複数オペレーターの同時操作
- 何手でも戻せる履歴

**大会当日に新機能を追加することは禁止です。**

## ファイルの地図

```
uizin-eventos/
├── core/          ← 依存ゼロ・純関数だけ。ここが仕様の正本
│   ├── types.ts     イベントステートの形
│   ├── state.ts     書き換え規則（reduce）
│   ├── timer.ts     タイマー計算
│   ├── history.ts   直前の一手だけ元に戻す
│   ├── music.ts     緑/黄/赤 の判定
│   ├── script.ts    MCの読み上げ文
│   ├── sheet.ts     スプレッドシート → 番組表
│   └── csv.ts       CSVパーサ
├── worker/        ← Cloudflare Workers（唯一の真実の置き場）
│   ├── index.ts     権限・スプレッドシート取得・リンク確認
│   ├── event-do.ts  Durable Object（状態・自動保存・WebSocket配信）
│   └── wrangler.toml
├── app/           ← Next.js（静的書き出し）。5画面
├── tests/         ← node --test（依存ゼロ・ネットワーク不要）
└── scripts/rehearsal.mjs  ← 3端末同期の実機スモークテスト
```
