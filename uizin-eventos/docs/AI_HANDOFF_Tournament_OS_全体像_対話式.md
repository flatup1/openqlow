## 2. 要望と決定（対話式）

### 2-1. 目的

**ユーザー：** 私が作った対戦カードを組むアプリを、他のジムの会長にセットアップしてもらいたい。小学生にも分かるように、できるだけ作業を短くしたい。

**AIの理解：** 目標は「**会長が一人で、15分以内に、新しい受付を作って、選手に渡すURLがコピーできる**」こと。範囲は「ひな形のコピーから、選手に渡すURLがコピーできるまで」。選手が申し込む待ち時間は入れない。**名簿の取り込みから対戦カード作成までの目標時間は、まだ決まっていない（要確認）。**

### 2-2. 個人情報

**ユーザー：** 個人情報をCloudflareに上げるのは論外。リスク0%になるまで検証と修正を繰り返して。

**AIの理解：** 選手の連絡先は、**会長本人のGoogle（スプレッドシートとDrive）だけ**。Cloudflareに置くのは、空の静的ページと、大会設定の雛形まで。選手の名前・写真・対戦表は、会長のPCのブラウザの中（IndexedDB）に取り込む。

**ユーザー（別のAIが出した案を貼ったあとの選択）：** 「私のv3で進める」。

**AIへの指示：** 別のAI（Codex）の案（氏名・写真・競技情報をCloudflareに保存、メール確認コード）は**採用していません**。再び検討するときは、**ユーザーの明示の決定**を取ってください。

### 2-3. 会長の作業を減らす（今回の中心）

**ユーザー：** GASを作る件なども簡略化したい。できるだけユーザーのやる作業を減らしたい。

**AIの対応：** 次の第3章に、作ったものを書きました。

### 2-4. 名簿の渡し方

**ユーザー：** アプリと実データを分ける構成にしたらどうか。アプリはCloudflareで公開し、実データを取るのは、エントリーの画面とGASとスプレッドシートにする。公開している対戦カードアプリの項目から、Googleスプレッドシートのcsvを読み込む構成にしたら楽では？

**AIの回答：** 実は今の作りが、ほぼその形。3つの案（GASに「名簿を返す入口」を足す／Googleの「ウェブに公開」でCSV／今のZIP）を比べた。

**ユーザーの選択：** 「3　今のZIPのままの構成を、小学生にも分かるように教えて」。

**決定：** **ZIPのまま**。（写真も一緒に運べる、一番安全、会長の手作業は3回：ZIPを作る・ダウンロード・アプリに入れる）

### 2-5. 申込ページの見た目

**ユーザー：** エントリーシートのUIを、今変えることはできる？

**AIの回答：** できる。ただし、**ユーザーが「どこをどう変えたいか」をまだ言っていない**。聞き返している最中。（文字を大きく／写真のところを分かりやすく／入力欄を減らす／色を変える、などの案を出した）

### 2-6. 案内のしかた（ユーザーからの繰り返しの要望）

- 日本語、結論ファースト、短く、**小学生にも分かる言葉**。
- **1回に、押すことは1つだけ。** 押す場所の名前（ボタンの文字）と、**成功の目印**を書く。
- 「採点して」と言われたら、**100点満点・項目別（汎用性25／自動実行性25／検証・採点精度20／安全性20／分かりやすさ10）で、証拠に基づいて**採点する。
- 100点にならないときは、**正直に**、点数・減点理由・残りを示す。

## 3. 会長のセットアップを短くするために作ったこと（小学生向けの説明）

### 3-1. 一言で

> 学校の「お手本ノート」を1冊だけ先に作っておく。会長さんは、そのノートを**コピーするだけ**。お手伝いロボットも、いっしょについてくる。

### 3-2. 前と後ろ

| | 前（v2） | 後ろ（v3.1） |
|---|---|---|
| ロボット（プログラム）をどう入れる | 会長が、長い文字をコピーして、Apps Script に貼って、保存する | **お手本のシートを、コピーするだけ**。ロボットもついてくる |
| 大会の情報を入れる場所 | 画面と、Googleのプログラムの**2か所** | **Googleのシートの「設定」タブの1か所だけ** |
| 大会ID | 会長が考えて入れる | **自動** |
| 確認コード（TOS2…）のコピー・貼り付け | 毎回、長い文字をコピーして貼る。15分で切れる | **なし**。画面が自動で確かめる |
| メールアドレスの入力 | 画面に入れる。アカウント違いで失敗しやすい | **入れない**。実行した本人が自動で記録される |
| テスト申込 | 会長が、手で架空の1件を送る | **「① 最初の設定」が、自動で架空の1件を書いて確かめる** |
| デプロイの「自分／全員」 | 会長が選ぶ | **最初から選ばれている**（`appsscript.json`） |
| 設定画面の段階 | 5段階 | **3段階** |
| 設定の間違い | 分かりにくいエラー | **どの欄をどう直すか**を言って止まる |

### 3-3. 会長の流れ（6つ）

1. 「ひな形のコピーを作る」を押す → Googleで「コピーを作成」を押す。
2. シートの「設定」タブに、6つの欄を書く（大会名・開催日・会場・主催者名・問い合わせ先・申込締切）。
3. メニュー「Tournament OS」→「① 最初の設定」を押す（許可の画面が出たら許可）。
4. 「拡張機能」→「Apps Script」→「デプロイ」→「ウェブアプリ」で公開して、URLをコピーして、アプリに貼る。
5. メニュー「② 受付を開始」を押す。
6. アプリの「選手へ渡すURLをコピー」を押す。

### 3-4. 選手の申込のデータが動く道（手紙でたとえる）

- 選手が、自分のスマホで受付ページを開く（Cloudflareの空の画面）。
- 写真は、スマホの中で小さくする。
- 「送信」を押すと、**会長のGoogleのURL（ロボットの入口）へ、直接**送られる。**Cloudflareを通らない。**
- ロボットが、シートに1行書き、写真をDriveの箱に入れる。
- 締切後、会長が「④ OS用の名簿ZIPを作る」→ダウンロード→アプリに取り込む。**連絡先はZIPに入れない。**

### 3-5. 守っているもの（変えていない）

- 連絡先は、会長本人のGoogleだけ。取込用の表・ZIP・画面が読む確認の返事に、**連絡先も、メールも、鍵も出ない**（テストで固定済み）。
- 申込表・写真フォルダは「会長本人だけ」。公開共有・直接共有されていたら、受付を止める。
- 数式になる文字の無害化、写真の検査、電話番号の先頭の0の保持、二重登録の防止、同時送信の順番待ち。

## 4. 現在地と点数

### 4-1. 点数：**80 / 100**

| 項目 | 配点 | 点数 | 理由 |
|---|---|---|---|
| 汎用性 | 25 | 21 | 大会ごとの設定・項目のON/OFF。別競技の実機例はまだ |
| 自動実行性 | 25 | 18 | v3.1で手作業を大きく減らした。**本物のGoogleで「① 最初の設定」・デプロイ・自動確認が通るまでは、これ以上つけない** |
| 検証・採点精度 | 20 | 18 | 自動テスト＋ブラウザ試験＋本物のGoogleでの一部確認 |
| 安全性 | 20 | 18 | 個人情報の線は変えていない |
| 分かりやすさ | 10 | 5 | **会長ご本人が一人で完了した実測がまだない** |

### 4-2. 本物のGoogleで確かめられたこと（2026-10-02〜06）

- 旧方式：設定→デプロイ→接続確認→架空の申込3件→表に1行→写真リンク→受付番号の表示。**電話番号の先頭の0が消える不具合を見つけて、直して、直ったことを確認。**
- **v3：お手本シートをコピーしたら、スクリプトも一緒にコピーされた**（Googleの画面に「添付の Apps Script ファイルと機能もコピーされます」と出た）。
- **v3：コピーしたシートに、メニュー「Tournament OS」と「設定」タブが自動で出た**（別アカウントで）。

### 4-3. 模擬Google／自動テストで確かめたこと

- 自動テスト283本（Google側のスクリプトの模擬16本、画面側とつなぎ目12本を含む）、型チェック、ビルド。
- ブラウザ試験：旧方式72項目、v3の設定画面56項目（PCとスマホのサイズ）。

### 4-4. **まだ確かめていないこと（断定しない）**

1. 本物のGoogleで、「① 最初の設定」（許可の画面・架空1件の自動テスト）。
2. ウェブアプリのデプロイ（通常ウィンドウ・1アカウント）。マニフェストの「自分で実行・全員がアクセス」が最初から選ばれるか。
3. 画面から確認（ping）が読めるか（CORS）。読めないときの代わり（出た文字を貼る）は作成済み。
4. 選手に渡すURLを、実スマホ・LINEの中で開いて申し込めるか。
5. Cloudflareへの公開（**ユーザーの明示の承認が必要**。旧 `pages:deploy`・旧Worker・旧go-liveは使わない。公開するのは `out-private-pages` だけ、新しいPagesプロジェクトで）。
6. 会長ご本人が、説明者なしで、15分以内に完了すること。

## 7. 会長・ユーザーを案内するときの「つまずき」の記録

| つまずき | 原因 | 対策 |
|---|---|---|
| 「主催者本人のGoogleへ切り替えてください」 | 画面に入れたメールと、実行中のアカウントが違った | v3では、メールを入れさせない（実行者を自動で記録） |
| 「401 invalid_client」 | Safariのプライベートウィンドウの承認ポップアップ | 通常ウィンドウ・1アカウントだけで行う |
| 「無題のプロジェクト」が増えた | 貼り付け先の取り違え | v3は、コピー方式で貼り付け自体をなくした |
| 古い大会のコードをコピーした | 古いタブからコピーした | 設定をコードに焼き込まない |
| 「この会長・大会の受付ではありません」 | 画面とプログラムの鍵の食い違い | 鍵そのものをなくした |
| ターミナルの命令のコピーで、リンクが上書きされた | **命令をコピーしたら、クリップボードの中身が変わる**（何度も発生） | **クリップボードを使わず、ターミナルに直接貼らせる**（`read` で入力を待つ） |
| アドレスをターミナルに入れてしまった | 入れる場所の取り違え | 「Safari/Chromeの上のアドレス欄」と場所を言う |
| ⌘ + Shift + R がリーダー表示になった | Safariでは、強く再読み込みではない | **Chromeは ⌘ + Shift + R、Safariは ⌘ + R** と、ブラウザごとに案内する |
| ファイル選択で「個人情報あり」のCSVが選ばれそうになった | 一覧の最上位にあった | 取込画面は、連絡先らしい列を見つけたら読み込まない |
| デスクトップにファイルができなかった | Macの権限 | 保存先を「ダウンロード」にして、`ls` で確かめる |
| スマホの Sheets アプリで「Tournament OS」メニューが出ない | アプリは、カスタムメニューを出さない | メニューを押す操作は、パソコンで |
| 画面だけで入力した日付が、区切りがばらばら（`2026-12/20`） | 手入力 | スクリプトは、混ざった区切りも読める（確認済みの設計） |
