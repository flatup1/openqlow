# 大会DJデスク（2026-09-20）

2026-09-20の確定仕様を `/dj/` に追加。既存の `/live/`、`/op/`、`/mc/`、`/screen/`、`/mix/`、`/check/` を残す。
このページがDJ画面の現行仕様。旧文書の「DJはv2」「音を鳴らさない」は、従来の画面についての説明。

## 当日の操作

1. 入口の「大会DJデスク」を開く。進行担当は「音源・音量設定」で操作キーを保存する。
2. REDは左、BLUEは右。選手カードでプロフィール、アナウンスで名前・ふりがな・意気込みを拡大する。
3. 入場曲を再生／開く。OS内の曲はNOW PLAYINGに表示され、停止・一時停止ができる。
4. 中央の進行ボタンで入場 → 試合 → 結果へ進む。Winner BGMで表彰、次の試合へ。
5. 誤操作はUndo（直前の進行操作のみ）。緊急停止は音声を即停止し、サーバーへ大会停止を送る。再開は確認が必要。

前／次／一覧の試合移動には、移動先の名前と確認を出す。再生中や表彰中は注意を添える。
二重クリック・古い状態からの操作は、画面のロックとサーバーの状態番号照合で拒否する。
通信エラーで結果が不明なときは自動再送せず、「最新状態を確認」する。

## 音源と保存

- 音声ファイルURL（mp3/m4a/aac/wav/ogg/opus）と、この端末で選んだ音声ファイルをOS内で再生できる。
- Apple Music / YouTube / その他のHTTP(S)リンクはDJ画面から外部へ開く。外部アプリの再生状態は不明と表示する。
- **外部アプリの音声はOSから停止できない。外部側で停止する。** 再生中と決めつけない。
- Winnerは5パッド、サンプラーは6パッド。名前・URL・音源ファイルを設定できる。音源は同時に1つ。
- Winner未設定時は既存music表の `kind=result` を順に利用する。音源未登録のパッドは鳴らない。
- MASTER / RED / BLUE / BGM・SAMPLERの音量、パッド名・URLはブラウザに保存する。
- **端末で選んだファイルはアップロードされず、再読込後に選び直す。** 著作物のダウンロードやサービス制限の回避はしない。
- 同じブラウザ・同じオリジンのDJ／かんたん進行タブは音声停止を共有する。別ブラウザの音声まで停止する保証はない。音響は1端末1タブで運用する。
- 音源を切り替えると前のOS内音声を停止する。再読込や緊急停止解除後の自動再生はしない。

## Google Sheets

既存の `event` / `matches` / `music` を引き続き使う。新しいスプレッドシートや受付システムは作らない。
読み込み専用。Sheetsの原本への書き戻しはない。連絡先・保護者情報などを含む申込原本は接続しない。

`matches` は既存どおり **1行1試合、`no` の昇順**。試合順を変える場合は `no` を変更する。
従来列に加えて、次の任意列を読める（赤は `red_`、青は `blue_`）。

| 接尾辞 | 内容 |
|---|---|
| `kana` / `name_kana` | ふりがな（未入力は「読み方未登録」） |
| `age`, `height`, `weight` | 年齢、身長、体重（単位はシートに記入） |
| `category`, `stance` | カテゴリー、構え |
| `music_url` / `entrance_music_url` | 選手本人の入場曲URL |

既存の `name` / `team` / `record` / `comment` / `photo` はそのまま使う。
入場曲は `music.match_no + kind` → 選手行のURL → 未紐付け曲の選手名（既存の曲名・備考を含む）の順で選ぶ。
選手名が曖昧・重複しているときや、別の試合へ紐付いている曲は推測で割り当てない。

「データ更新」で取り込み、最終取込日時を表示する。失敗時・空の取込・進行中の現在試合消失時は前のデータを保つ。
取込後のUndoは無効（旧番組表と新状態の混在を防ぐ）。シートを修正して再取り込みする。

## 復元と限界

大会進行は従来のDurable Objectが正本。最後に受信した正常な大会データを接続先別に端末へ保存する。
通信断で再読込しても、静的画面が読み込める限り選手名・プロフィール・意気込み・現在試合を表示できる。
キャッシュは閲覧用。未接続時にサーバー上の試合を進めたり、端末間同期した扱いにはしない。
再接続後はサーバーの状態を採用する。アプリ本体を完全オフラインで新規起動するService Workerは今回の範囲外。

## 仕様照合

| 確定仕様 | 実装 |
|---|---|
| DJ型・RED/BLUE・詳細プロフィール | `/dj/`、選手カード |
| 大文字の意気込み／アナウンス | 個別ダイアログ、既存`/mc/`にもふりがな |
| 入場曲／NOW PLAYING／停止 | 1音源の再生制御、外部リンクは区別 |
| Winner BGM／サンプラー | 5＋6パッド、設定を端末保存 |
| 前／次／状態／Undo／緊急停止 | 既存進行コマンドと確認・状態番号照合 |
| Sheets取込／欠損耐性／復元 | 既存取込の拡張・正常データ保持・端末キャッシュ |

配信・OBS・電子ゴング・採点・受付は追加しない。

## 本番へ反映する前

`npm run verify`（単体テスト＋Next.js build）とリポジトリ共通の `bash scripts/validate-ai-os.sh` を実行する。
ローカルWorkerの模擬3接続同期・停止／復帰と、ブラウザの5試合通し操作を検証する。
これらは会場の実機3端末やスピーカー出力の実証とは別。

**フロントとWorkerは同じ版を揃えて公開する。** 新クライアントは操作の状態番号を送り、Workerが照合する。
古い画面を開いた端末は公開後に再読込する。既存の写真API・表示画面・進行表を維持する。
