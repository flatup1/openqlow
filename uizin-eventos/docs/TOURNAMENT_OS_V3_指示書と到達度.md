## 0. 結論（先に読む）

- いまの仕組みは**動く**。本物のGoogleで、受付→写真保存→電話番号の0保持まで確認できた（2026-10-03）。
- ただし**会長が一人で作れない**。設定だけで約25クリック・Googleの画面3つ・コードの貼り付け3回。今日も、アカウント違い／別プロジェクト／古い画面のコピーで何度も止まった。
- 作り変えの中心は3つ。
  1. **コードを貼らない**（ひな形シートの「コピーを作る」1回にする）
  2. **確認コード（TOS2）の手貼りをやめる**（画面が自動で確かめる）
  3. **設定はシートの「設定」タブが正本にする**（直すたびにコードを貼り替えない）
- 個人情報の線引きは**変えない**。連絡先は会長のGoogleの中だけ。OSが読むのは「連絡先なし」の取込用だけ。
- 「Cloudflareで一元管理」は、**個人情報を含まない範囲**を既定にした（下の「決めてほしいこと」D1・D2）。

## 2. 作り変えの目的と、守るもの

### 目的
PCに不慣れな会長が、**一人で・何度でも・同じ結果で**、大会の受付とOSを作れること。

### 受け入れ基準（数値で決める）

| 項目 | 基準 |
|---|---|
| 設定の操作回数 | 25回 → **12回以内** |
| 所要時間 | **15分以内**。範囲は「ひな形のコピーから、選手に渡すURLがコピーできるまで」（オーナー回答 2026-10-04）。選手が申し込む待ち時間は入れない。名簿の取り込みから対戦カード作成までの目標時間は、別に決める（未決） |
| コード・鍵・確認コードの手貼り | **0回**（貼るのは、ウェブアプリのURL 1回だけ） |
| Googleの画面 | 3つ → **1つ**（ひな形のコピー＋自分のシート上で完結） |
| やり直し | どの手順でも、同じ大会IDで再実行して**壊れない**（冪等） |
| 全部作り直し | 「ひな形をもう一度コピー」だけで、新しい受付箱ができる |
| 会長が迷ったとき | 画面に「いまここ（5段階のうち何番目）」と「次の1つ」だけが出る |
| 検証 | 会長役の非エンジニア1名が**一人で**完了（記録を残す） |

### 絶対に守るもの（壊さない）

1. **個人情報（電話・メール・保護者名・住所・生年月日）は、会長本人のGoogleの中だけに置く。** Cloudflare・GitHub・チャット・ログに出さない。
2. **OSが読む名簿は「連絡先なし」だけ。** ZIPに連絡先を入れない。取込画面は連絡先らしい列を見つけたら読み込まない（`privateHeaders`）。
3. 申込表・写真フォルダは「制限付き・主催者本人だけ」。共有が広がっていたら受付を止める（`isPrivateOwned_`）。
4. 公開の申込ページは、会長自身のウェブアプリURLにだけ送る（`connect-src 'none'`、`form-action` は script.google.com のみ）。
5. 申込の二重登録を防ぐ（requestId による冪等）と、同時送信の順番待ち（Lock）。
6. 数式として解釈される文字（`= + - @`）の無害化（`clean_`）、写真の形式・サイズ検査、電話番号の文字保持。
7. 原本は読み取り専用。削除・全面上書きをしない。
8. テストは架空データだけ。本物の連絡先は使わない。

## 3. v3 の設計

### 3-0. 全体図

```
会長のブラウザ                    Cloudflare Pages（静的ページだけ）
  ├─ 準備画面 /private/  ─────── 空の画面を配るだけ（データは持たない）
  ├─ 受付画面 /apply/#…  ─────── 空の画面を配るだけ
  └─ 当日画面 /private/live/

会長のGoogle（会長本人のアカウント）
  └─ 「Tournament OS 受付」シート（ひな形のコピー）＋ そこに付いたスクリプト
       ├─ 設定 タブ        …大会名・締切・項目（ここが正本）
       ├─ 申込原本（個人情報あり）…連絡先はここだけ
       ├─ OS取込用（連絡先なし）…OSが読むのはここだけ
       └─ 写真フォルダ（Drive）
```

### 3-1. コードを貼らない：ひな形シートのコピー方式

- オーナーのGoogleに「Tournament OS 受付ひな形」（**コードと見出しだけ、個人情報なし**）を置き、「リンクを知っている人はコピー可」にする。
- 会長はコピー用リンクを開き「コピーを作成」を押すだけ。**スクリプトも一緒にコピーされる**（コンテナバインド）。
- 開くと上部に**メニュー「Tournament OS」**が出る（`onOpen`）。
  - 「① 最初の設定」→ 設定タブを読み、申込表・写真フォルダ・見出しを作る（`setupTournament`、冪等）。
  - 「② 受付を開始」→ `openEntries`
  - 「③ 受付を停止」→ `closeEntries`
  - 「④ OS用の名簿ZIPを作る」→ `exportTournament`
  - 「⑤ いまの状態を表示」→ 5段階のチェック表示
- ウェブアプリの**デプロイだけは手動で残る**（「デプロイ」→「新しいデプロイ」→「ウェブアプリ」）。ここは1回だけ。画面の説明を1画面にまとめる。
- ひな形を更新したときは、会長は「もう一度コピー」するだけ。新しい受付箱ができる（古い箱は消さない）。
- **要検証（実機で先に確かめる。ここが崩れたら設計を戻す）**
  1. 「コピーを作成」でスクリプトも一緒にコピーされるか、コピー先のメニュー（`onOpen`）が初回から出るか。
  2. コピー先で初回に出る「承認が必要です／Googleで確認されていません」の画面の文言と、押す順番（詳細→移動→許可）。
  3. コピーした側のウェブアプリのデプロイが、通常ウィンドウ・1アカウントだけで通るか（今日は、プライベートウィンドウで承認ポップアップが失敗した）。

### 3-2. 確認コード（TOS2）をやめる：自動確認

- 現状: 署名付きコード（HMAC・setupKey・nonce・15分/5分の窓）を会長が**コピーして貼る**。
- v3: 画面が、会長が貼ったウェブアプリURLへ `GET …/exec?action=ping` を送り、次だけを受け取る。
  `{ app:'tournament-os', build, eventId, accepting, testComplete }`（**主催者のメール・鍵・個人情報は返さない**）
- 画面が `build` と `eventId` を照合する。違えば「古い版です。『デプロイを管理』→『新バージョン』」を1行で出す。
- 画面側のCORS・CSPは、**準備画面だけ** `connect-src` に `https://script.google.com https://script.googleusercontent.com` を足す（受付画面は `'none'` のまま）。
- **要検証**: Apps Script のウェブアプリへの GET は、CORS で読めるか実機で確認する（読めない場合は、白い確認ページの1回コピー方式に戻す。コピー1回なら許容）。

### 3-3. 実行者の自動記録：メールを入力させない

- `setupTournament` 実行時に `Session.getEffectiveUser().getEmail()` を **所有者として保存**（Script Properties）。以後の `assertOwner_` はこの保存値と照合する。
- これで「画面にメールを入れる」「アカウント違い」の事故が構造的に消える。ひな形はコピーした人のアカウントで動く。

### 3-4. 設定の正本は「設定」タブ

- 大会名・締切・入場曲ON/OFF・学年/年齢/意気込みの必須/任意/なし、を**シートの「設定」タブ**に置く。
- スクリプトは毎回そこを読む。**コードに焼き込まない。** 締切を変えるのに、コードの貼り替えは要らない。
- `policy_()` の照合（画面側の値とGoogle側の値の一致確認）は廃止。画面は `ping` で受け取った設定をそのまま使う。

### 3-5. 廃止する／残すセキュリティ機能

**廃止してよい（会長の手間の原因・守る対象が別の仕組みで守られている）**

| 機能 | 廃止の理由 | 代わりに守るもの |
|---|---|---|
| `setupKey` と HMAC署名コード（TOS2） | 手貼り・食い違いの主因。コードは個人情報を守る機能ではなく、接続確認の改ざん防止だった | `ping` の照合＋実行者本人の保存（§3-3） |
| 確認コードの有効時間（15分／5分／issuedAt窓） | 時間切れ事故の原因 | 不要（`ping` は都度） |
| `challenge` / `nonce` | 同上 | 同上 |
| `testKey` と `entryKey` の2本立て | 鍵が2つ・長いURLの原因 | 1本の `mode`（test／live）。テストは**架空データ専用のシート**に入る |
| `expectedOwner`（画面で入力するメール） | 入力ミス・アカウント違いの原因 | 保存した実行者との照合 |
| `policy_()` 照合 | コード貼り替えが必要になる原因 | 設定タブが正本 |
| `RECEPTION_BUILD` ゲートの人手更新 | 古い版の事故 | `ping` が自動表示 |

**残す（個人情報・原本を守る）**

- 申込表・写真フォルダの**非公開確認**（`isPrivateOwned_`）
- **連絡先を取込用に出さない**、取込側で連絡先列を検出したら止める
- `clean_`（数式注入対策）、写真の形式・サイズ検査、電話番号の文字保持
- requestId の冪等と Lock
- 受付ページのCSP（`connect-src 'none'`）と、保存先URLの形式検査（`script.google.com/macros/s/…/exec` のみ）
- 同意チェック、ハニーポット（`website` 欄。コストが小さい）
- 件数上限（3000件）。レート制限（毎分30件）は**簡略化可**（残してもよい）

> **廃止は1つずつ**。各項目を外す前に、「代わりに守るもの」のテストを先に書く。外したあとも、`npm test`・ブラウザ試験・本物のGoogleでの1件送信を通す。

### 3-6. Cloudflare の担当

| 置く | 置かない |
|---|---|
| OSの静的ページ（準備・受付・当日） | 選手の名前・写真・体重・連絡先 |
| 大会設定の**雛形**（項目の定義） | 申込データ |
| 公開の配布ファイル（ひな形リンクの案内ページ） | 認証鍵・パスワード |

- **Phase A（既定・サーバーなし）**: 静的ページのみ。設定は現状どおり**URLのハッシュ**で受け渡す。短くしたい場合は、設定をJSONファイル1つに書き出し／読み込みできるようにする（個人情報・鍵なし）。
- **Phase B（任意・D1で承認されたら）**: Cloudflare KV に**大会設定だけ**（個人情報なし）を置き、受付URLを `/e/<短いコード>` にする。名簿・写真・対戦表は置かない。
- 旧Worker＋Durable Object（個人情報を受ける旧設計）は**復活させない**。

### 3-7. 名簿・対戦カード

- 名簿（名前・ジム・体重・写真）は今まで通り**会長のPCのブラウザ（IndexedDB）**。暗号化バックアップあり。
- 取込は、(a) 会長が作るZIP（`players.csv`＋`photos/`）、(b) CSV、(c) Excel。いずれも連絡先なし。
- 対戦カードの注意（今日追加）: 体重差5kg以上／同ジム／同じ選手が2試合以上。**保存は止めない**。5kgは大会ごとに変えられるようにする（次の作業）。

## 4. 作業指示（順番どおりに）

各フェーズの終わりに、`npm test`・`npx tsc --noEmit`・`npm run build:private`・ブラウザ試験（`scripts/test-private-browser.mjs`）を実行し、**結果を貼る**こと。

### フェーズ0: 土台を固める（コードを大きく変えない）
1. 対戦カード警告の commit（承認後）。体重差のしきい値を設定可能にする。
2. 古いテスト行の削除手順を会長向けに書く（行を選んで削除するだけ）。**実行は会長自身**。
3. 取込側で、ZIPに連絡先らしい列があれば止まることを、テストで固定する（既存の `privateHeaders` に不足がないか確認）。

### フェーズ1: スクリプトの設定化と自動確認（`public/templates/Tournament_OS_Google受付.gs`）
1. 「設定」タブを正本にする。`SETTINGS` の焼き込みを廃止。
2. `onOpen` のメニューと、`setupTournament`／`openEntries`／`closeEntries`／`exportTournament` の接続。
3. `doGet` に `action=ping`（返すのは §3-2 の項目だけ）。
4. 実行者の自動記録（§3-3）。
5. 旧プロトコル2との互換は、`protocol` 値で分ける。v3が実機で通るまで、旧版は消さない。
6. `tests/gasReception.test.ts` を更新（模擬Googleに `onOpen`・設定タブ・`ping` を足す）。**「連絡先がOS用・ZIP・ping応答に出ない」テストを必ず足す。**

### フェーズ2: 設定画面（`app/private/google-setup/page.tsx`）
1. 5段階を4段階に減らす: ①ひな形をコピー ②メニューから最初の設定 ③デプロイしてURLを貼る ④テスト1件を送る。
2. TOS2 の貼り付け欄を削除し、`ping` の自動確認にする。**失敗時は次の1つだけを出す**（アカウント違い／古い版／まだ受付前、のどれか）。
3. 画面の最上部に「いまここ（n/4）」と「次の1つ」を固定表示。
4. 設定の書き出し／読み込み（JSON、鍵なし）。別のPCでも、ここから再開できる。
5. ブラウザ試験を更新。

### フェーズ3: 本物のGoogleで通す（オーナーのテスト用アカウント）
1. 新しいひな形のコピー → 設定 → デプロイ → `ping` → 架空1件 → 電話の0 → 取込用シート → ZIP → `/private/` 取込 → 対戦カード。
2. **会長役の非エンジニア1名が、手順書だけで一人で完了。** 詰まった箇所を記録し、画面を直す。
3. 失敗の再現: アカウント違い・古い版・未デプロイ・時間切れ後、の4つで画面の案内を確認。

### フェーズ4: スマホ・LINE・公開
1. 実スマホ（iPhone Safari／Android Chrome／LINE内ブラウザ）で受付画面を通す。
2. Cloudflareへの公開は、**`out-private-pages` のみ**。**新規Pagesプロジェクト**。公開前に、`_headers` のCSPと、公開物に個人情報・鍵がないことを確認する。
3. 公開は**オーナーの明示承認の後**。旧 `pages:deploy`・旧go-live・旧Worker deploy は**使わない**。

### フェーズ5: 再構築の手順書（会長用）
1. 1ページ・大きな文字・スクリーンショット付きの手順書を作る。
2. 「困ったとき」を1ページ（アカウント違い／古い版／最初からやり直す）にまとめる。
3. 「全部作り直す」手順: ひな形をもう一度コピー → 新しい大会IDで設定。古い箱は消さない。

### 何を調べたか

### 最初の敵対テストで見つかったアプリの不具合5つ（すべて対応済み。5つ目は意図して対応しない）
1. 【P2】保存したあと1.5秒以内に1文字直して下のボタンを押しても、何も起きなかった。→ 「未保存」か「保存失敗」のときは、必ず保存するようにした。二度押し防止は、保存ずみで何も変わっていないときだけ。
2. 【P2】`/private/setup/` の手順2で「次へ進む」をダブルクリックすると、手順2にもどって「何も起きない」ように見えた（PC幅）。→ 手順を変えて0.7秒以内の「もどる」は無視するようにした。
3. 【P3】URLのような長い名前を入れると、横にはみ出した。→ 折り返しと `min-w-0` を付けた。
4. 【P3】書きかけの日付（例: 2027年10月）が、ほかの欄に移ると書き換わった。→ 日付がそろったときだけ整えるようにした。
5. 【P4】手順2で、URLを入れる前は目立つボタンが0個。→ 会長の判断待ちとして、直していない。

あわせて、前から壊れていた単体テストを1つ直した（`setup/page.tsx` の固定文字を、共通の判定関数に置き換え）。
