## 0. 依頼の整理

| 項目 | 内容 |
|---|---|
| **目的** | **インターネットが落ちても、UIZIN 2026 の進行を止めないこと。** |
| **対象者** | 大会当日のスタッフ（オペレーター・MC・音響・大型モニター係）。**初見・5分説明で使えること。** |
| **完成物** | ①オフラインで動く単一HTMLファイルを作る生成スクリプト ②そのHTMLを印刷した紙の進行台本（同じファイルから出る） |
| **制約** | 費用¥0／依存パッケージ追加ゼロ／**既存の EventOS（`core/` `worker/` `app/`）の動作を変えない**／個人情報をリポジトリに入れない |
| **優先順位** | 1.止まらないこと → 2.一目で分かること → 3.工数の小ささ → 4.見た目 |
| **成功条件** | 後述の [§4 100点の判定基準](#4-100点の判定基準) を**全項目満たすこと** |

### なぜこれを作るのか（背景）

EventOS v1.0 は完成し、本番公開も済んでいます（`uizin-eventos.pages.dev`）。
しかし**全画面がインターネット越しにサーバーと通信し続ける設計**のため、**会場の回線が落ちると5画面すべてが同時に死にます。**

体育館・多目的ホールは電波が悪くなりがちです（鉄骨・コンクリート・観客数百人が同じ電波を共有）。
つまり現状は「**システムが止まらないこと**」しか考えられておらず、「**システムが止まっても大会が止まらないこと**」の備えがゼロです。

この指示書は、その**2枚目と3枚目の床**を敷く作業です。

```
第1層  EventOS（同期あり・すでにある）    ← ネットが生きている間
  ↓ 落ちたら
第2層  オフラインHTML（今回作るもの）      ← ネットが死んでも動く
  ↓ それも無理なら
第3層  紙の進行台本（同じHTMLを印刷）      ← 何が起きても読める
```

## 2. 作るもの

### 2-1. 生成スクリプト `scripts/build-offline.mjs`

```bash
# 使い方（どれか）
node scripts/build-offline.mjs --sheet <進行表のシートID>   # ネットから取ってくる（本番用）
node scripts/build-offline.mjs --dir <CSVが入ったフォルダ>   # 手元のCSVから作る
node scripts/build-offline.mjs --demo                      # 架空データで作る（開発中はこれ）
```

`--demo` は `tests/fixtures-offline.ts` の架空データを使う。**開発と動作確認はすべて `--demo` で行うこと。**
本物の進行表（選手名・意気込みが入っている）を開発中に使ってはいけない。

- 出力先: `out-offline/uizin-offline.html`（**1ファイルだけ**）
- `package.json` に `"offline": "node scripts/build-offline.mjs"` を追加する
- `--sheet` は `https://docs.google.com/spreadsheets/d/<ID>/gviz/tq?tqx=out:csv&sheet=<タブ名>` を3回叩く
  （`worker/index.ts` の `loadSheets` と同じ形。**HTMLが返ってきたら「シートが公開されていません」と日本語で止める**。既存の `looksLikeHtml` を使う）
- 失敗したら、**何が悪くて何をすればいいかを日本語1〜2行で**出して終了する

### 2-2. 出力される `uizin-offline.html` の要件

**これがこの作業の本体です。**

#### 絶対条件（1つでも欠けたら未完成）

1. **外部への通信を一切しない。** `fetch` / `XMLHttpRequest` / `WebSocket` / `<script src>` / `<link href>` / `<img src="http...">` を**1つも含まない**
2. **`file://` で開いて完全に動く。** ダブルクリックだけ。サーバー不要・ネット不要
3. **データはファイル内に埋め込む。** 対戦カード・選手名・所属・戦績・意気込み・入場曲URL・タイマー秒数、すべて
4. **1ファイルで完結する。** CSS も JS も画像もインライン。添付ファイルなし

> 入場曲の `<a href="https://music.apple.com/...">` は**残してよい**（リンクは人が押すもので、押した時だけ通信が起きる）。
> 押せなくても進行は止まらない、という前提を守ること。

#### 画面（1画面に全部入れる。切り替えを作らない）

JIN の要望そのままです:

> **一目で使える対戦カードと赤青コーナー、入場曲、マイクの人も意気込みを読みやすい**

| 出すもの | どう出すか |
|---|---|
| **対戦カード** | 画面の主役。**赤コーナーを左、青コーナーを右**に、色で塗り分ける |
| 選手名 | **一番大きい文字**。所属・戦績はその下に小さく |
| **意気込み** | **MC がそのまま読める大きさ**（最低 24px 相当、長文でも折り返して全部見える。省略記号で切らない） |
| **入場曲** | 曲名・アーティストと、Apple Music / YouTube へのリンク。緑黄赤の色も出す |
| 次の試合 | 画面の隅に小さく（今の試合の邪魔をしない） |
| タイマー | Event Timer と Round Timer を**上部の同じ位置に常時**。端末内で動く |
| 進捗 | 「3 / 12 試合」 |

#### 操作（覚えることを3つ以内にする）

| キー | 動き |
|---|---|
| **スペース** | 次へ（試合を進める） |
| **Esc** | 停止／再開（「しばらくお待ちください」を大きく出す） |
| **← →** | 試合を前後に選び直す |

- 画面にも大きなボタンを置く（タッチ端末のため）
- **保存ボタンは作らない**（EventOS と同じ思想）
- 現在位置は `localStorage` に自動保存し、**再読み込みで元の試合に戻る**

#### 印刷（第3層＝紙）

- `Cmd+P` / `Ctrl+P` で**A4縦の進行台本**になること
- 印刷時は**全試合を上から順に一覧**（1試合＝1ブロック）。画面用のボタン・タイマーは印刷しない
- **MC がそのまま読める**こと（意気込みを省略しない、小さくしない）
- `@media print` で実装する

#### 端末

- Mac / Windows / iPhone / iPad / Android の標準ブラウザで開ける
- **横幅400pxでも崩れない**（スマホで開く係がいる前提）
- 暗い会場で見るので**黒背景・高コントラスト**（EventOS の `/screen/` に合わせる）

## 4. 100点の判定基準

node scripts/build-offline.mjs --demo
open out-offline/uizin-offline.html # 目で見て確認（Linux なら xdg-open）

**手で確かめること（自動テストでは見えない）:**

1. Wi-Fi を切る → HTMLをダブルクリック → **全部動くか**
2. スペースキーだけで最後の試合まで進めるか
3. Esc で「しばらくお待ちください」が大きく出るか
4. `Cmd+P` の印刷プレビューで、意気込みが切れていないか
5. ブラウザ幅を400pxまで縮めて崩れないか

## 7. 絶対に守ること

### 安全

| | |
|---|---|
| 🚫 | **`out-offline/` をコミットしない。** 選手名・意気込みが入る（`.gitignore` 登録済み。外さないこと） |

| ✋ | **外部への送信・公開・課金・元に戻せない操作は、実行前に必ず人間（JIN）の確認を取る**。Cloudflare への再デプロイもこれに含む |

## 8. 最終報告の形式

作業が終わったら、**この順番で**報告してください。

```
1. 完成したもの／達成した結果
2. 実施した主な改善
3. 検証内容と結果（コマンドと実際の出力）
4. 最終得点と採点根拠（§4 の表を項目ごとに ✅/❌ と点数で）
5. 残っている課題やリスク
6. JIN が次に行うべき一手（なければ「なし」）
```

**採点は感覚で100点にしないこと。** テスト結果・実際に動かした結果・成果物という証拠に基づいて付けること。
権限や環境の制約で100点にできない場合は、**無理に100点とせず、到達できた点数と阻害要因を正直に書く**こと。
