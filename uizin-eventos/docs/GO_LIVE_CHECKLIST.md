## 1. 実データ検証でわかったこと

### 共有忘れを実機で再現して見つけた欠陥（修正済み）

`SHEET_ID` を実際の進行表に設定したまま、共有が「オーナーのみ」の状態で「取り込み直す」を押す、
という**これから必ず通る状態**を再現したところ、次の壊れ方が見つかりました。

**Google は、公開されていないシートに対して CSV ではなくログイン画面のHTMLを HTTP 200 で返します。**
`res.ok` だけを見ていたため、そのHTMLをCSVとして取り込み、**試合0件の番組表で上書き**していました。
進行中にこれが起きると、走っている大会から対戦カードが消えます。

二重に塞ぎました。

1. Worker が取得した中身がHTMLなら、**取り込む前に**失敗させ、共有設定を直すよう明示する
2. Durable Object 側でも、**進行中に「試合0件」で上書きすることを拒否**する（消し間違い・SHEET_IDの入れ違いも防ぐ）

実機で確認した挙動:

```text
① 進行中に「試合0件」を取り込もうとする
   → HTTP 409 / kept:true / 「大会が進行中のため、今の番組表を残しました」
   → 番組表・進行状態ともに無傷

② ログイン画面のHTMLを取り込もうとする
   → 同上。取り込まれない

③ 開始前に空の番組表へ入れ替える
   → HTTP 200。準備中の入れ替えは妨げない

（共有オーナーのみのシートに対する取り込み）
   → HTTP 502 / kept:true
   → 「シート「event」を読めませんでした（HTTP 403）。共有設定を…にしてください。」
   → 既存の番組表と進行状態は保持される
```

### 直したこと（コード側）

| 見つかったこと | 実データでの症状 | 直したこと |
|---|---|---|
| 申込シートの入場曲は **1列**（`入場曲URL（Apple Music推奨）`）しかない | Apple/YouTube の2列を前提にしていたため、**41件のURLが全部「未登録＝赤」**になった | 1列で来たURLを Apple / YouTube に**自動で振り分ける**ようにした |
| 曲名とURLが同じセルに混ざる（`ターミネーター２ https://…`／`PROVANT(https://…)`） | URLとして読めず赤 | セルからURLだけを抜き出すようにした |
| Apple でも YouTube でもないURLが実際に貼られている（Amazon Music・LINE・Googleの広告リンク） | 「Apple MusicのURLではありません」としか出ず、何をすればいいか分からない | **サービス名を名指し**して「貼り替えてください」と出すようにした |
| 入場曲を使わない選手がいる | 空欄が全部赤になり、**赤がゼロにならず運用が成立しない** | 空欄（未確認）＝赤、`なし`と明記＝灰（対象外）に分けた |
| 黄が38件出て、赤17件が埋もれた | 直すべきものが見つけられない | チェック画面を**直すべき順（赤→黄→灰→緑）**に並べ替えた |

## 2. 本番投入までに必要なこと

### ステップ1: 進行表スプレッドシートを新しく作る ✅ **完了（2026-09-08）**

**申込の原本（`UIZIN 2026 大会エントリー`）を EventOS に繋いではいけません。**
連絡先メール・電話番号・保護者氏名が入っており、EventOS は「リンクを知っている全員」の共有を必要とするため、
そのまま繋ぐと個人情報が公開されます。

新しく `UIZIN 2026 進行表（EventOS用）` を作り、`event` / `matches` / `music` の3タブだけを置きます。

**雛形は用意済みです。**

- Excelファイル `UIZIN2026_進行表_EventOS用.xlsx`（3タブ＋使い方タブ入り。Googleドライブへアップロードして
  「Google スプレッドシートとして開く」だけで、タブ名も見出しも揃った状態になります）
- CSVの雛形: [templates/](templates/)（1タブずつ取り込む場合）

書き方の詳細は [SPREADSHEET_TEMPLATE.md](SPREADSHEET_TEMPLATE.md)。

- `music` タブは、マッチメイクタブの `名前` と `入場曲` をコピーするだけで作れます（1列のままで構いません）
- 共有設定は **「リンクを知っている全員」＋「閲覧者」**（編集者にはしない）

### ステップ2: 対戦カードを確定する ❌ **未着手（ここが最大の詰まり）**

`matches` タブが **0件**のままです。このままだと試合を1つも進められず、
**3端末リハーサルも1回もできません。**

**確定を待たないでください。暫定で入れて構いません。**
変わったら書き換えて `/op/` の「取り込み直す」を押すだけで反映されます。

`matches` タブに必要なのは、1行 = 1試合で次の列です。

```
no,class,rule,rounds,round_seconds,break_seconds,red_name,red_team,red_record,red_comment,blue_name,blue_team,blue_record,blue_comment,note
1,キッズ,アマチュアキックボクシング,2,1:30,60,赤の選手名,赤の所属,赤の戦績,赤の意気込み,青の選手名,青の所属,青の戦績,青の意気込み,
```

選手名・所属・戦績・意気込みは、マッチメイクタブからそのままコピーできます。

## 3. EventOS では直せない、報告事項

- **申込データに文字化けがあります。** 例: 意気込みの絵文字が `ð¥` のような壊れた文字になっている行があります。
  MC画面・表示画面にはシートの文字がそのまま出るので、**進行表にコピーするときに直してください**。
  （EventOS 側では、壊れた文字か正しい文字かを区別できません）
- **広報利用に「不同意」の選手が3名います。** 意気込みや所属を会場モニターに出してよいかは、
  同意の範囲の問題なので JIN の判断です。EventOS は進行表に書いてあるものをそのまま出します。
- 申込には**テスト行**（選手名「あ」など）が混ざっています。進行表には入れないでください。
