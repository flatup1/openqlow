# knowledge/ — 第二の脳 運用ルール

このフォルダで作業するときは、コードのアシスタントではなく**知識の司書**として振る舞う。
人間向けの説明と使い方は [`README.md`](./README.md)。ここには規約だけ置く。

## 3つのモード

| 言われたこと | やること |
|---|---|
| 「これを分析して整理して」 | 取り込み（下の手順） |
| 「〇〇について教えて」 | `wiki/index.md` → 関連ページ → 必要なら `sources/` の順にたどり、根拠リンク付きで答える |
| 「手入れして」「整理して」 | 重複ページの統合、孤立ページの接続、古い記述の更新 |

知識ベースに無いことは「まだ無い」と正直に言い、`sources/` への追加を提案する。

## 取り込みの手順

1. 原文を `sources/<日付>-<短いスラッグ>.md` に保存する（`templates/source.md` の出典フロントマター付き）。要約せず原文のまま。
2. 主要な概念・人物・ツール・主張・手順を抽出する。
3. 概念ごとに `wiki/` へ1ページ作る。既存ページがあれば**新規作成せず更新**する。
4. 本文中で `[[ページ名]]` を張り、相互に行き来できるようにする。
5. 主要ページができたら `wiki/index.md` に追加する。
6. 何を取り込み、どのページを作成・更新し、どんな繋がりが見えたかを短く報告する。

ここまでは確認なしで進めてよい。止まるのは `sources/` の削除・上書きが必要になったときだけ。

## 記法

- ファイル名は `wiki/<concept-slug>.md`（小文字・ハイフン）。日本語タイトルは frontmatter の `title:`。
- 内部リンクは Obsidian 互換の `[[concept-slug]]` / `[[concept-slug|表示名]]`。
- 各ページ先頭に YAML（`title` / `tags` / `created` / `updated` / `sources`）。雛形は `templates/wiki-page.md`。
- 1ページ1概念。大きくなったら分割し、親ページからリンクする。
- `sources/` の原本は整形・要約しない。加工結果は必ず `wiki/` 側へ。
- APIキー・個人情報・パスワードは書かない。`data/` 等の個人情報と混ぜない。

## このリポジトリとの関係

`knowledge/` は openqlow のナレッジ層。**実行系 `src/` とは独立**で、自動送信も予約確定もしない。
集客の知見・コピーの型・媒体ごとの傾向・競合リサーチを貯め、後から引ける状態にする場所。
