# CONTENT_STRATEGY — コンテンツとSEO

## コピーの中心思想

主人公はユーザー。コピーは「私たちはすごい」ではなく **「あなたにもできる」**。

| ✕ | ○ |
|---|---|
| 強くなれ | 始めてみませんか |
| 限界を超えろ | あなたのペースで大丈夫 |
| | 初心者歓迎 |
| | ◎ 初めての人のために作った場所です |

過剰に弱々しいブランドにはしない。「優しい」と「かっこいい」を両立する。

## コンテンツの切替（Progressive Disclosure）

回答によって、文章・写真・動画・口コミ・FAQ・クラス案内・インストラクター情報・
CTA・体験案内を切り替える（→ PERSONALIZATION.md）。
ユーザーが選択していない情報は原則表示しない。

## 事実の正本

料金・営業時間・クラス・住所などの事実は `openqlow/src/shared/canon.ts` を正本とする。
WebOSのコンテンツに事実を直書きして二重管理にしない（Phase 2で正本接続）。
Phase 1では事実を含む表示を最小限に留める。

## SEO — 「見せない」と「隠す」を混同しない

WebOS化しても検索流入を捨てない。

- **ユーザーには**: 必要な情報だけを見せる（質問UI）。
- **検索エンジンには**: 情報を提供する。

質問UIの裏側とは別に、以下をSEOで必要な公開情報として検索エンジンが理解できる構造にする:

- ジム基本情報 / クラス / 料金 / アクセス / キッズ / レディース / 初心者向け / FAQ

実装手段（Phase 2以降）: 静的な情報ページ群 + 構造化データ（JSON-LD。
既存LP `flatup-lp/index.html` に `SportsActivityLocation` の実装例あり）。

## キッズ二層コンテンツ

- 保護者向け: 安全・礼儀・成長・見学のしやすさ・料金の明瞭さ
- 子ども向け: 楽しさ・冒険・かっこよさ
