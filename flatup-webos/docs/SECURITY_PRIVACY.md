# SECURITY_PRIVACY — 個人情報・秘密情報・承認境界

## 基本原則

1. **secretsをGitへ入れない。** `.env` をコミットしない。APIキー・トークンは
   環境変数またはVPS側の設定で管理する。
2. **顧客個人情報を表示・保存・コミットしない。**（openqlow共通ルール）
3. **個人情報・センシティブ情報の保存は、必要最小限・明示的同意・安全性を優先。**

## Phase 1のデータ扱い

- ユーザー回答（audience / goal / experience / availability 等）は
  **ブラウザの sessionStorage のみ**に保持。サーバーへ送信しない。
- 氏名・連絡先などのPIIはPhase 1では一切収集しない。
- 性別は必須にしない。スキップ可能とし、回答しなくても体験が劣化しないようにする。

## Phase 2以降（AI・予約接続時）の原則

- WebからAIへコンテキストを渡すのは **カテゴリ情報のみ**（例: 初心者/夜/ダイエット）。
  自由入力・PIIを渡す場合は明示的同意を取る。
- AIチャットのログを保存する場合はPIIマスクを通す
  （flatup-ai-os `sanitizePii` に実装済みの前例あり: 電話/メール/カード番号のマスク）。
- 通信はHTTPSのみ。VPS API接続時はCORS・レート制限・入力検証を実装する。
- プロンプトインジェクション対策: ユーザー入力より正本知識を優先。
  AIに送信・予約確定・料金判断の権限を与えない。

## 承認境界（openqlow準拠）

以下は必ず人間（JIN）の承認後のみ:

- 送信 / 予約確定 / 料金判断 / 返金 / 退会 / 休会
- 外部書き込み / 公開 / 課金 / 本番反映
- merge / deploy / サーバー設定変更 / ファイル削除

AIは下書き・分析・提案・リスク整理まで。

## 検証

- 変更後は `./scripts/validate-ai-os.sh` と関連テストを実行する。
- コミット前に diff に秘密情報・PIIが含まれないことを確認する。
