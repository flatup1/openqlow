# FLAT UP WebOS — AGENTS.md（AI憲法）

Claude Code・Codex・その他のAIがこのプロジェクトを触るとき、必ず最初に読むルールです。
親リポジトリ openqlow の `AGENTS.md` と `COORDINATION.md` が上位にあります。矛盾したら親が優先。

## 絶対に守ること

1. **North Starを変更しない。**
   「世界一優しい格闘技ジム FLAT UP GYMへ、ユーザーを迷わせず、必要な情報だけを必要な瞬間に届け、
   安心して最初の一歩＝体験予約まで進める世界一優しいWebOSをつくる。」
2. **全面書き換え禁止。** 小さな差分を優先する。
3. **既存機能を確認してから変更する。** 変更前後の動作を確認する。
4. **テストなしの大規模変更禁止。**
5. **モバイル優先。** PCから作ってスマホへ縮小する思想は禁止。
6. **セキュリティ優先。** secretsをGitへ入れない。`.env` をコミットしない。
7. **UXの複雑化禁止。** 迷った場合は機能を足すのではなく減らす。
8. **新規依存を増やす前に必要性を説明する。** 既存資産 > 無料OSS > 安価な既存サービス > 新規有料サービス。
9. **既存資産を再利用する。** openqlow / flatup-lp / VPS / LINE の既存構成を壊さない。
10. **ユーザーに同じ入力を繰り返させない。** Web→AI→LINEで文脈を引き継ぐ設計を守る。

## このリポジトリ固有のルール（openqlow準拠）

- コミットメッセージ先頭に発信元AIを書く: `claude: ...` / `codex: ...`
- 送信・予約確定・料金判断・本番反映・merge は **JIN（オーナー）承認後のみ**。
- 顧客個人情報・秘密情報を表示・保存・コミットしない。
- 料金・時間・クラス等の事実は `openqlow/src/shared/canon.ts` を正本とする。推測で書かない。
- 変更後は `./scripts/validate-ai-os.sh` と関連テストを実行する。

## 開発の進め方

常にこの順番で進める。**一度に全部作ることは禁止。**

```text
設計 → 最小実装 → テスト → 採点 → 改善 → 次のPhase
```

各Phase終了時に必ず実施:

- **TEST**: build / lint / typecheck / automated tests / mobile layout /
  major browser / console errors / broken links（可能な範囲ですべて）
- **採点**: UX・優しさ・分かりやすさ・スマホ操作性・表示速度・保守性・予約導線・
  ブランド整合・セキュリティ・完成度で100点満点。90点未満なら問題点を列挙し改善する。
  ただし採点のために不要な機能を追加しない。
- **報告**: `DONE / CHANGED / TESTED / SCORE / KNOWN ISSUES / NEXT` の6項目のみで報告する。

## オーナーへの説明ルール

オーナー（JIN）は開発者ではない。専門用語を並べず、**中学生でも理解できる日本語**で、

- 今どこまで完成したか
- 残り何があるか
- 次に何をするか

を必ず明示する。

## 判断に迷ったら（合言葉）

> 見せすぎない。聞きすぎない。迷わせない。同じことを二度聞かない。
> 必要なときに、必要なことだけ。主役はユーザー。
> 小さく完成させて、大きく育てる。

「ここなら私でも大丈夫かも」と思えて、そのまま自然に体験予約できる。**
