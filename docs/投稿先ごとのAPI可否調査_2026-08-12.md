# 投稿先ごとの API 可否調査

> 調査日 2026-08-12 / 調査: Claude
> 目的: 「JIN本人が手を動かさずに全投稿先へ出す」ために、各投稿先が**公開APIで投稿できるか**を確定する。
> ブラウザ投稿はログインセッションが切れるたび人手が要るため、恒久的な自動化にはAPIが要る。

## 結論

| 投稿先 | 公開API | 判定 | 本人操作 |
|---|---|---|---|
| Instagram | Graph API | ✅ **稼働中** | 済み |
| Threads | Threads API | ✅ **可能** | 認可1回 |
| Googleビジネス | Business Profile API `localPosts.create` | 🟡 **可能。ただし利用申請と審査が要る** | 申請＋認可1回 |
| LINE VOOM | **見つからない** | 🔴 **ブラウザ運用のみ** | 都度ログイン |

**4つ中3つはAPIで完全自動化できる。ブラウザ運用が必要なのは LINE VOOM だけ。**

---

## Googleビジネス

### 投稿API は存在する（廃止されていない）

- エンドポイント: `POST https://mybusiness.googleapis.com/v4/{parent=accounts/*/locations/*}/localPosts`
- 2022年4月に旧 My Business API が5つの専用APIへ分割されたが、
  **`localPosts` の投稿作成は現在も有効**。定期投稿の作成にも対応している。

### ただし「承認ゲート」がある — ここが実質の壁

- Business Profile API は**既定で閉じている**。新規のGoogle Cloudプロジェクトは
  **クォータがゼロ**の状態で始まり、そのままではAPIを呼べない。
- 利用開始には**手動の一回限りの利用申請と承認**が必要。
- 申請時に求められるもの:
  - 正当な利用目的（自社または顧客の店舗管理）
  - **60日以上運用されている認証済みのGoogleビジネスプロフィール**
  - 有効な事業用ウェブサイト
  - GCPプロジェクト番号、連絡先、必要なスコープ
- 申請フォームで「Application for Basic API Access」を選ぶ。
- **審査はおよそ14日**。結果はメールで通知される。
- 承認されると8つのAPIに標準クォータが付与される。

### つまり

「今日やって今日動く」ものではない。**申請を出してから2週間待つ**必要がある。
逆に言えば、**申請を早く出すほど早く自動化が始まる**ので、着手は早い方がよい。

## LINE VOOM

### 公開の投稿APIは確認できなかった

- LINE Messaging API は**ユーザーへのメッセージ送信**のためのもので、VOOMへの投稿機能は見当たらない。
- VOOM への投稿は **LINE VOOM Studio** または **LINE公式アカウントマネージャー**（いずれもWeb画面）から行う仕様。
- VOOM Studio は公式アカウントの管理者権限を持つ人が使える。

> 注意: 「見つからなかった」であって「絶対に存在しない」と断定はできない。
> ただし公開ドキュメント上に投稿エンドポイントが見当たらない以上、
> **現時点ではブラウザ運用を前提に設計するのが妥当**。

### つまり

LINE VOOM だけは、ブラウザでログインした状態から投稿するしかない。
ここは `browser:jobs` → 画面で投稿 → `browser:done` の経路を使い続ける。

## 設計への反映

1. **Threads**: トークンを入れるだけ。コードは完成済み（`threads_api.ts` / `npm run threads:check`）。
2. **Googleビジネス**: 利用申請を先に出す。承認後、`localPosts.create` を叩くアダプタを実装し、
   `final_publish.ts` の `google_business` 分岐をブラウザ退避からAPI投稿へ差し替える。
   （Threads/Instagramと同じ形なので、実装自体は既存パターンの踏襲で済む）
3. **LINE VOOM**: ブラウザ経路を維持。ログインセッションが切れる前提で、
   「投稿待ちが溜まっていること」をJINに気づかせる通知があるとよい。
