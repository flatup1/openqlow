## §0 このシステムは何か（誰が見てもわかる説明）

FLATUP GYM（千葉県成田市の格闘技ジム）が、**お客様対応と経営判断をAIで回すための仕組み**です。
AIは2体いて、役割がはっきり分かれています。

```
        お客様                          オーナー（JIN）
          │                                   │
     LINEで質問                          今日やること
          │                                   │
          ▼                                   ▼
    ┌───────────┐                    ┌───────────┐
    │   AIKA    │                    │  openQLOW │
    │  守りのAI  │                    │  攻めのAI  │
    │  受付・返信 │                    │ 営業・経営支援│
    └─────┬─────┘                    └─────┬─────┘
          │                                 │
          └────────────┬────────────────────┘
                       ▼
          ┌──────────────────────────┐
          │  正本 canon.ts            │
          │  料金・時間・クラスの      │
          │  たった1つの正しい答え     │
          └──────────────────────────┘
```

**大事な原則がひとつだけあります。**

> 事実（料金・時間・クラス）を書いていい場所は、世界に**1か所だけ**。
> 他の全部は、そこから写した「コピー」。

なぜなら、2か所に書くと必ずズレるからです。今回見つかった不具合5件は**すべてコピー側のズレ**でした。

### AIが絶対にやらないこと

送信・予約確定・料金判断・返金・退会・休会・本番反映は、**必ず人間が最後に決めます**。
AIは下書きと整理までです。

## §2 発言から読み取れる要求（対話式）

**Q. JINが最終的に欲しいものは何ですか？**

> 最適化とはユーザーに対しての返信がおかしくないこと

お客様がLINEで質問したとき、**AIKAが嘘の時間・嘘の料金を答えない状態**。これがゴールです。
コードの美しさやアーキテクチャの刷新は求められていません。

**Q. どこを直せば「返信がおかしくない」状態になりますか？**

> その証本データはリポジトリなので修正と最適化を口返して

（「証本」＝正本、「口返して」＝繰り返して、と読みます）

AIKAの返信は**リポジトリに置かれた正本データ**から作られます。だから直す対象はリポジトリ。
そして一度きりではなく、**ズレを見つけては直すことを繰り返します**。具体的な場所は §4 に全部書きました。

**Q. 進め方の条件は？**

> 最短最速最低工数で実践したい　最低価格で最大限に効果を出し出い　コスパタイパを意識して

大きな作り直しはしません。**効果が大きく工数が小さい順**に手をつけます。

**Q. 報告の仕方に条件はありますか？**

> 中学生にもわかるように教えて
> 残りの作業を可視化して
> 必ず採点してから残りの作業がどの程度あって何をやっているのかを説明して
> 次の一手を教えて

毎回この4点セットです。**採点 → 残作業の可視化 → 次の一手**の順で、専門用語を避けて書きます。

**Q. リポジトリはどこですか？**

> AIKAにはAIKAのリポジトい　OPEN QLOWにも適したリポジトリがあるハス　探して最適化したい

探した結果、3つ見つかりました（§3）。

**Q. JINはターミナルに慣れていますか？**

慣れていません。実際に次のつまずきが起きました。**受け手のAIは必ず配慮してください。**

- `（Vaultのフォルダ）` のような**説明用の仮の文字をそのまま入力した** → プレースホルダを残さず、実際のパスを書くこと
- `#` で始まるコメント行を**コマンドとして入力した**（zshでは `command not found`）→ **コメントを混ぜない**
- ページャー（`less`）が開いたまま `:` で止まり、**同じ出力を何度も貼り直した** → 長い出力を求めない。求めるなら `--no-pager` か `| cat` を付ける
- **複数のコマンドを渡すと途中を飛ばす** → 1回に1〜2個まで。飛ばされたら責めずに、飛んだ分だけ再提示する
