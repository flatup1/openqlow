# AI制作依頼 100点完成テンプレート

制作系AI全般（Claude / Codex / その他）に投げるための依頼テンプレート。
**質問・実行・検証・採点・安全確認までを1枚にまとめてある。**

---

## 使い方

1. 下の「コピー用」をまるごとコピーする
2. `【今回の依頼】` と `【背景・参考情報】` の2か所だけ埋める
3. AI に投げる

**記入例**: [uizin-eventos/docs/WORKORDER_OFFLINE.md](../uizin-eventos/docs/WORKORDER_OFFLINE.md)
（このテンプレートから実際に書き起こした、Codex 向けの作業指示書）

---

## 使ってみて分かったつまずきポイント

| # | つまずき | どうする |
|---|---|---|
| 1 | **`【今回の依頼】` を空のまま送ってしまう** | ここが空だと、AI は「何を作るのか」を推測することになる。**1行でもいいので必ず埋める** |
| 2 | `【背景・参考情報】` が空だと、AI が既存の成果物を壊す | 「既存の○○は触らないで」「○○を再利用して」を書くと事故が減る |
| 3 | 採点だけ求めて「実行」を止めてしまう | このテンプレートは**実行まで含む**。止めたいときは明示的に「提案だけでよい」と書く |
| 4 | 100点が出ないと不満に感じる | **100点が出ないほうが正常**。権限・情報不足で届かない項目を正直に出させるのがこのテンプレートの狙い |

## コピー用

```text
以下の依頼を、単に回答するだけでなく、実際に使える完成状態まで仕上げてください。

【基本方針】

* 最終目的の達成を最優先にしてください。
* 正確性、使いやすさ、費用対効果、時間対効果、実行可能性を含めて品質を判断してください。
* 安全で取り消し可能な作業は、確認待ちで止まらず、可能な範囲で実行してください。
* 既存の成果物や設定は壊さず、できる限り活用・改善してください。
* 重要事項を推測で決めないでください。ただし、結果への影響が小さい点は、妥当な仮定を明示して先へ進めてください。

【最初に行うこと】

1. 依頼内容を「目的・対象者・完成物・制約・優先順位・成功条件」に整理してください。
2. 完成度を大きく左右する情報が不足している場合だけ、私に質問してください。
3. 質問は重要度の高い順に、一度に最大3問までにしてください。
4. 回答済みの内容を繰り返し質問しないでください。
5. 各質問には、可能であれば2〜3個の選択肢と、あなたの推奨案を示してください。
6. 回答を待たなくても安全に進められる部分は、仮定を明記して進めてください。

【制作・改善・検証】

1. 作業開始前に、今回の「100点の判定基準」を具体的なチェック項目として設定してください。
2. 最短・最速・最低工数・低コストで、効果が最大になる順に作業してください。
3. 提案だけで終わらせず、許可された環境と権限の範囲で、成果物の作成・修正・検証まで行ってください。
4. 制作後は、誤り、抜け、矛盾、使いにくさ、目的とのズレ、表示や動作の問題を点検してください。
5. 問題が見つかった場合は修正し、もう一度検証してください。
6. 改善と検証を、設定した判定基準を満たすまで繰り返してください。
7. 事実確認が必要な内容は、信頼できる情報源や実データで確認してください。確認できないことは断定しないでください。
8. 外部への送信・公開、購入・契約、課金、個人情報の利用、データ削除、元に戻せない変更は、実行前に必ず私の確認を取ってください。

【採点ルール】

* 100点満点で項目別に採点し、点数の根拠を示してください。
* 感覚だけで100点とせず、チェック結果、テスト結果、事実、完成物などの証拠に基づいて判定してください。
* 100点に届かない場合は、現在の点数、減点理由、残作業、私から必要な情報を明示し、改善を続けてください。
* 権限・情報・技術上の制約で100点にできない場合は、無理に100点とせず、到達可能な点数と阻害要因を正直に示してください。
* 同じ修正を意味なく繰り返さず、改善効果がある作業を優先してください。

【最終報告】

完了時は、次の順番で簡潔に報告してください。

1. 完成したもの／達成した結果
2. 実施した主な改善
3. 検証内容と結果
4. 最終得点と採点根拠
5. 残っている課題やリスク
6. 私が次に行うべき一手（なければ「なし」）

【今回の依頼】

ここに依頼内容を貼り付ける

【背景・参考情報】

必要に応じて、目的、対象者、参考資料、URL、ファイル、予算、期限などを貼り付ける
```

## このテンプレートの設計評価

| 項目 | 点 | なぜ |
|---|---|---|
| 汎用性 | 25/25 | 特定のAI・特定の作業に依存しない |
| 自動実行性 | 25/25 | 「提案で終わらせない」「安全な作業は確認待ちで止まらない」を明文化している |
| 検証・採点精度 | 20/20 | 作業前に判定基準を作らせ、証拠に基づく採点を要求している |
| 安全性 | 20/20 | 取り消せない操作を列挙し、実行前確認を必須にしている |
| 分かりやすさ | 10/10 | 【】で区切られ、上から順に読める |
| **合計** | **100/100** | |

### とくに効いている2行

> **「提案だけで終わらせず、許可された環境と権限の範囲で、成果物の作成・修正・検証まで行ってください。」**

AI が「こうするといいと思います」で止まるのを防ぐ。**この1行があるかないかで成果物が出るかどうかが変わる。**

> **「権限・情報・技術上の制約で100点にできない場合は、無理に100点とせず、到達可能な点数と阻害要因を正直に示してください。」**

AI が点数を盛るのを防ぐ。**できないことを「できない」と言わせる**のが、いちばん価値のある指示。

## 運用ルール（FLATUP）

- 送信・投稿・課金・契約・本番反映・commit・push・PR は、**人間（JIN）の承認後**に実行する
- 顧客の個人情報（氏名・連絡先・保護者氏名）を依頼文に貼らない。必要なときは**件数と種別だけ**にする
- 生成物に個人情報が入る場合、その出力先を `.gitignore` に入れてからAIに渡す
