# 読み取り専用からの接続手順（READONLY_ROLLOUT）

`MCP_SETUP.md` が「候補の台帳」なのに対し、本書は **実際に接続を始める順番** を決めるものです。
新しい仕組みは作りません。このリポジトリに既にある DRY-RUN と承認ゲートを使います。

原則：**読み取り → 下書き → 承認つき書き込み**。この順を飛ばさない。

---

## 前提：すでに存在する安全装置

| 装置 | 実体 | 役割 |
|---|---|---|
| DRY-RUN | `OPENQLOW_DRY_RUN` / `OPENQLOW_LINE_DRY_RUN` | 送信せずに出力だけ確認する |
| 隔離起動 | Skill `run-openqlow-dryrun` | Vault・LINE本番に触れずに起動する |
| 危険操作の遮断 | `.claude/hooks/guard-command.sh` / `.codex/hooks/guard-command.sh` | 削除・force push・外部送信を deny/ask |
| 承認区分 | `docs/ai-os/canon/approval_matrix.md` | 何を人間が決めるか |
| 事実の正本 | `src/shared/canon.ts` | 料金・時間を1か所で管理 |

秘密情報はファイルへ直書きせず、`.env`（Git管理外）に環境変数として置きます。
本書には**変数名のみ**を書き、値は書きません。

---

## フェーズ0：接続せずに検証する（今すぐ実施可能）

接続前に、出力品質と承認境界だけを確かめます。コストも顧客影響もありません。

1. `run-openqlow-dryrun` の手順で隔離起動する。
2. `flatup-inquiry-reply` などで下書きを出す。
3. `flatup-content-qc` で料金・日時・誇大表現・個人情報を検品する。
4. `bash scripts/validate-ai-os.sh` で正本のズレが無いことを確認する。

**フェーズ1へ進む条件**：3回連続で、料金・日時の誤りゼロ。

---

## フェーズ1：読み取りだけつなぐ

| サービス | 使う環境変数（値は書かない） | 読み取る対象 | この段階で禁止 |
|---|---|---|---|
| LINE公式 | `LINE_CHANNEL_SECRET`, `LINE_CHANNEL_ACCESS_TOKEN` | 受信メッセージ、問い合わせ傾向 | push / reply（`OPENQLOW_LINE_DRY_RUN=true` を維持） |
| Googleスプレッドシート | （接続時に定義） | 会員数・体験数の集計値 | セルの書き込み・共有設定変更 |
| Instagram / GBP | `IG_ACCESS_TOKEN`, `GOOGLE_BUSINESS_ACCESS_TOKEN` | 公開済み投稿の反応 | 投稿・広告・返信 |
| 会費ペイ | （API有無を先に確認） | 契約・入金の**件数のみ** | 契約変更・課金・返金 |

### 守ること

- **氏名・電話・LINE ID・子どもの情報・病歴・決済情報を Git 管理下に保存しない。**
  集計値（人数・件数）だけを扱い、個人が特定できる行は持ち出さない。
- 読み取り結果をログに残す場合も、個人情報は伏せる。
- 接続できない場合は**架空の値で埋めず「未取得」**と書く（`flatup-weekly-kpi` の規則）。

**フェーズ2へ進む条件**：`flatup-weekly-kpi` が2週続けて、手作業の数字と一致すること。

---

## フェーズ2：承認つきで書き込む

書き込みは**1サービスずつ**、必ず次の型で止めてから実行します（`AGENTS.md` 準拠）。

```md
確認が必要です。
対象: {{対象}}
内容: {{実行すること}}
リスク: {{誤送信/削除/本番反映/料金判断など}}

この内容で進めてもよろしいでしょうか？
```

解禁の順序（安全な順）：

1. Googleスプレッドシートへの集計書き込み（顧客に影響しない）
2. Googleビジネスプロフィール／Instagram の投稿（撤回可能）
3. LINE の送信（撤回できない・最後）

**会費ペイの課金・契約変更・返金は、AI からは実行しない。** 常に人間が操作します。

---

## 中止と切り戻し

- 迷ったら `OPENQLOW_LINE_DRY_RUN=true` に戻す。これで送信は止まります。
- 誤送信が起きた場合は、追加送信で取り繕わず、事実を人間へ報告して指示を待つ。
- トークンが漏れた疑いがあるときは、該当サービス側で失効させてから再発行する。

---

## 定時実行との関係

自動化してよいのは**読み取り・集計だけ**です（`AUTOMATION_SETUP.md`）。
フェーズ2に進んでも、SNS投稿・LINE送信・メール送信の自動実行は行いません。
