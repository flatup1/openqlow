目的: Phase 4 に **最初の1件** を入れ、「使える1本あたりいくらか」を実際に出す

> Phase 4 で作ったのは「測る道具」です。現時点で記録は0件で、道具が本当に使えるかは未検証です。

## これだけは守る（3つ）

1. **わからないものは空欄。「0」と書かない。**
   0は「ゼロだった」、空欄は「まだ調べていない」。混ぜると数字が全部くるいます。
   （実装上も `null` と `0` は別物として保存されます — SCHEMA_CATALOG §1 / AT-019）

2. **予測と実測は別の欄。足して2で割らない。**
   予測は勘、実測は事実。混ぜると両方使えなくなります。
   （実装上も別型・別ラベルで保存され、平均値はどこにも作られません — AT-020）

3. **次に変えるのは1つだけ。**
   Hookも尺もCTAも一度に変えると、何が効いたのか永久にわかりません。
   （1つだけなら `one_variable`、複数なら `exploratory` になり学びに使えません — AT-021 / AT-022）

## ⑤ 答えを出す（約3分）

```
使える1本あたりの費用 ＝ 費用 ÷ 使えた本数
```

例: 1000円で10本つくって、使えたのが2本 → 1000 ÷ 2 ＝ **500円**（AT-017）

**使えた本数が0本のときは計算しません。**「計算できない（使えたものが無い）」と書きます。
ここに「0円」と書くと、失敗したのに安く済んだように見えてしまいます（AT-018）。

## 次にやること（2分）

次の1本で変えるのは、この中から **1つだけ**:

- [ ] Hook（最初の3秒）だけを変える
- [ ] 尺だけを変える
- [ ] CTA（最後の一言）だけを変える

他はぜんぶ同じにします（相手・素材・出す場所・出す時間帯）。そろえないと比べられません。

**3件たまったら、はじめて「学び」になります。**
1回うまくいっただけでは、たまたまかもしれません。同じやり方で3回そろって、はじめて
「これは本当だ」と言えます（Phase 5 の `validated_learning` 要件）。

## 実装との対応

このシートの各欄は Phase 4 の契約にそのまま対応します。

| シートの欄 | 実装 |
| --- | --- |
| ①の予測点 | `recordPredictedScore()` → `PredictedEmotionalScore.total_100` |
| ②の費用・使えた本数 | `summarizeCost()` → `CostSummary` |
| ②の1本ずつの判定 | `assessQuality()` → `QualityAssessment`（`human` 判定のみ usable に計上） |
| ④の指標 | `importMetricSnapshot()` → `MetricSnapshot.values`（空欄は `null`） |
| ⑤の1本あたり | `CostSummary.effective_cost_per_usable`（usable=0 なら `null` + `no_usable_output`） |
| ⑤の予測と実測 | `buildOutcomeView()` → `predicted` / `measured` を分離、`averaging_allowed: false` |
| 次にやること | `designExperiment()` → `one_variable` / `exploratory` |

手入力には `entered_by`（誰が）・`entered_at`（いつ）・`evidence_reference`（何を見て）が必須です。
シートを埋めた人と日時、見たインサイト画面の保存名を控えておいてください。
