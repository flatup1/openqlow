## 0. このスコアボードの原則

- 見る導線はひとつだけ。**体験予約 → 入会 → 継続 → 口コミ → 紹介**。
- 数字は**週に1回だけ確定させる**（月曜）。毎日は「詰まりの検知」だけ。
- **投稿数・広告本数はスコアボードに載せない**。それは作業量であって成果ではない。載せるのは導線の通過数だけ。
- openQLOWは数える・並べる・下書きする。**送信・確定・金銭はJIN**。

### いま自動で取れる数字 / 手で入れる数字

正直に分けておく。ここを混ぜると「動いているつもり」の運用になる。

| 段階 | 取得方法 | 根拠 |
|---|---|---|
| 問い合わせ数 | **自動**（CRM）`getNewInquiriesOn` | `src/crm/queries.ts` |
| 体験予約数 | **自動**（CRM）`getTrialScheduled` | 同上 |
| 体験実施数 | **自動**（CRM）status=`trial_done` | `src/crm/prospect.ts` |
| 入会数 | **自動**（CRM）status=`joined` / `joined===1` | 同上 |
| 失注数と理由 | **自動**（CRM）status=`lost` / `lostReason` | 同上 |
| 追客漏れ | **自動**（CRM）`getFollowupNeeded`（既定24時間） | `src/crm/queries.ts` |
| 口コミ依頼の候補 | **自動**（CRM）`getReviewRequestCandidates` | 同上 |
| **継続・退会（既存会員）** | **手入力**。CRMは入会で終わる設計で、会員の継続を追跡していない | `Prospect` に退会フィールドなし |
| **実際に投稿された口コミ件数** | **手入力**。Googleの口コミ数は取得していない | 未接続 |
| **紹介の発生** | **手入力**（`contactSource` に「紹介」と記録する運用で代替） | 専用フィールドなし |

> 未接続のものを「自動で見える」と書かない。手入力の3つは、JINまたはスタッフが月曜に数えて記録する。

## 1. 体験予約（入口）

**最低限記録する数字**

| 数字 | 定義 |
|---|---|
| 今週の問い合わせ数 | CRMに新規登録された件数 |
| 今週の体験予約数 | status が `trial_scheduled` になった件数 |
| 今週の体験実施数 | status が `trial_done` になった件数 |
| 予約→実施の到達率 | 実施数 ÷ 予約数 |
| 24時間以上未返信の件数 | `getFollowupNeeded` の件数 |

**数字の意味**
問い合わせ数は「知られているか」。予約数は「話が伝わったか」。実施数は「実際に来たか」。予約と実施の差が大きいときは、案内文ではなく**日程確定の遅さ**が原因のことが多い。

**警戒する状態**
- 24時間以上未返信が1件でもある（最優先の異常）
- 予約→実施の到達率が7割を切る
- 問い合わせはあるのに予約に進まない週が2週続く

**次に確認すること**
1. 未返信の件は、AIKAの下書きが出ていたのにJINが送っていないのか、下書き自体が無いのか。
2. 予約が実施に至らなかった人の `lostReason` と `memo`。
3. 問い合わせ元（`contactSource`）の内訳。どこから来た人が予約まで進んでいないか。

**推奨アクション**
- 未返信ゼロにする（他の何より先）。
- 日程候補を2つ以上添えて返す（選ぶだけにする）。
- 実施率が低い週は、前日リマインドの下書きを追加する。

**JINの承認が必要な操作**
返信の送信、体験日時の確定、リマインドの送信。openQLOWは下書きまで。

## 2. 入会

**最低限記録する数字**

| 数字 | 定義 |
|---|---|
| 今週の入会数 | status が `joined` になった件数 |
| 体験→入会の転換率 | 入会数 ÷ 体験実施数 |
| 未決の体験者数 | `getTrialFollowupNeeded` の件数（体験済み・未入会） |
| 失注数と理由の内訳 | `lostReason` の集計 |

**数字の意味**
転換率は「体験の中身」と「体験後24〜72時間の接触」の合計点。転換率が落ちたとき、原因は当日の体験より**その後の沈黙**であることが多い。

**警戒する状態**
- 体験→入会の転換率が5割を切る
- 体験済み・未入会が5件以上たまっている
- `lostReason` に「料金」が3週続けて最多で入る

**次に確認すること**
1. 体験済み・未入会の人に、翌日フォローの下書きが出ているか（`npm run trial-followup`）。
2. 失注理由が料金なら、**値下げではなく**説明順の問題か（何にお金を払うのかが伝わっているか）。
3. 入会時チェックリスト（退会規定・違約金条件の説明）が実施され、LINEに記録が残っているか。

**推奨アクション**
- 体験当日中にお礼、翌日にフォロー、3日後に入会案内。押し込まない。
- 転換率の低下が2週続いたら、体験の流れ自体を1つだけ変えて次週比較する。

**JINの承認が必要な操作**
フォロー文の送信、入会手続き、料金の個別対応。**値引きの判断はJINのみ**（安売りはブランド禁止事項）。

## 3. 継続（会員の維持）

> **この段階の数字は自動で取れない。** 月曜に手で記録する。

**最低限記録する数字**

| 数字 | 定義 |
|---|---|
| 在籍会員数 | 月初時点の実数（手入力） |
| 今月の退会申請数 | 退会届を受理した件数（手入力） |
| 退会率 | 退会数 ÷ 在籍数（月次） |
| 30日以上来館のない会員数 | 手で確認（入館記録またはクラスの出欠） |
| 目標までの残り | 100 − 在籍会員数 |

**数字の意味**
入口をどれだけ広げても、退会がそれを上回れば会員数は増えない。**継続はいちばん安い集客**。

**警戒する状態**
- 退会率が5%を超える（canon_2026 の抑制目標は3〜5%以下）
- 30日以上来館のない会員が増えている（退会の予兆）
- 退会理由に「人間関係」「指導」が出る（ブランドの根幹に関わる。10_AIKA_SAFETY_CASEBOOK_50 の事例37・40・44）

**次に確認すること**
1. 退会理由の内訳。金銭か、時間か、人間関係か、成果実感か。
2. 退会申請が「当月申請・翌月末退会」で正しく処理され、**退会完了控え**まで渡っているか。
3. 来館の空いている会員に、声かけの下書きを出せる状態か。

**推奨アクション**
- 来館が空いた会員へ、営業ではない一言の下書きを作る（「またお待ちしています」で終わる短文）。
- 退会者には引き止めず感謝で締める。**退会体験が良ければ口コミと再入会が残る**。

**JINの承認が必要な操作**
すべての送信。退会処理・返金・違約金の判定（Lv3・AI禁止）。

## 4. 口コミ

**最低限記録する数字**

| 数字 | 定義 |
|---|---|
| 口コミ依頼の候補数 | `npm run crm -- followups` の「口コミ依頼候補」件数（自動） |
| 今週の依頼送信数 | JINが実際に送った数（手入力） |
| 今週増えた口コミ件数 | Googleで手で数える（手入力） |
| 依頼→投稿の転換率 | 増えた件数 ÷ 送信数 |

**数字の意味**
口コミは紹介の燃料であり、次の問い合わせの入口でもある。**依頼していないから増えない**が最も多い原因で、内容が悪いからではない。

**警戒する状態**
- 候補はいるのに送信数が0の週が続く
- 転換率が2割を切る（タイミングが遅すぎる可能性）
- ネガティブな口コミが投稿された（事例47の運用へ即移行）

**次に確認すること**
1. 依頼のタイミングが「良い体験の直後」になっているか。
2. 依頼文が押し付けになっていないか。
3. ネガティブな内容が投稿された場合、JINが直接対応しているか（openQLOWは返信しない）。

**推奨アクション**
- 入会直後と、上達を実感した瞬間の2回だけ依頼する。それ以上は追わない。
- 依頼は下書きのままJINへ渡す。

**JINの承認が必要な操作**
依頼の送信、口コミへの返信。**口コミへの返信をAIが自動投稿することは禁止**。

## 5. 紹介

**最低限記録する数字**

| 数字 | 定義 |
|---|---|
| 紹介経由の問い合わせ数 | `contactSource` に紹介と記録された件数（手入力運用） |
| 紹介からの入会数 | 上記のうち `joined` |
| 紹介特典の付与数 | バンテージを渡した数（手入力） |

**数字の意味**
紹介は**費用ゼロで転換率が最も高い**導線。紹介経由の入会が1件出た週は、広告を1本増やすより価値がある。

**警戒する状態**
- 紹介経由が4週連続でゼロ
- 特典（FLATUPバンテージ）の存在を会員が知らない
- 紹介された人が「知り合いがいるのに一人で来た」状態で不安になっている

**次に確認すること**
1. 会員が紹介特典を知っているか（案内した記録があるか）。
2. 紹介しやすい形になっているか（誰かに送れる1通の文があるか）。
3. 紹介者と被紹介者の両方に特典が渡ったか（片方だけだと次が起きない）。

**推奨アクション**
- 紹介を「お願い」しない。**紹介できる道具を渡す**（そのまま転送できる短い案内文）。
- 紹介が発生したら、両者への御礼の下書きをその週のうちに出す。

**JINの承認が必要な操作**
案内の送信、特典の付与、キャンペーン条件の確定。

## 7. 目標との距離（参考・数字はJIN確認）

会員100人が目標、現在は約70名（canon_2026 §4）。

- 必要な純増は **+30人**。
- 退会率を4%と仮定すると、在籍70人で月およそ**3人が退会**する。
- 月の入会が3人なら会員数は横ばい。**月6人の入会で純増3人**、100人まで約10ヶ月。
- 月8人の入会なら純増5人、約6ヶ月。

> ⚠️ 上の月次ペースは canon_2026 の数字からの**逆算であり、オーナーが確定した週次目標ではない**。
> 旧目標「体験50本・入会25〜30人」は100人達成まで保留とされている（canon_2026 §4）。
> **週あたり何本の体験・何人の入会を目標にするかは、JINが決めてこの節に書き込む。**
