## 0. 前提（すでに main / PR #34 にある完成品）

- Instagram は Graph API で**自動投稿できている**（本番確認済み）。触らないこと。
- 残りの3つ（`threads` / `google_business` / `line_voom`）はログインが要るため、
  承認時に**ブラウザ投稿ジョブとして積まれるだけ**で、まだ実際には出ていない。
- そのジョブをブラウザエージェントが処理するための口は**もう用意されている**。

| コマンド | 役割 |
|---|---|
| `npm run browser:jobs` | 投稿待ちを一覧（人が読む形） |
| `npm run browser:jobs -- --json` | 同上（あなたが読む形） |
| `npm run browser:done -- <recordId> <destination> <投稿URL>` | 投稿できたと記録 |
| `npm run browser:done -- <recordId> <destination> --error "理由"` | 投稿できなかったと記録 |

手順の詳細は `docs/codex-browser-posting.md`。本書はその実行依頼。

## 環境

- VPS 上のコード: `/opt/openqlow`
- env: `/etc/openqlow/openqlow.env`
- 公開画像の置き場: `/var/www/openqlow-media`（nginx が配信）

## T1【最優先】画像の公開URLを有効にする

**なぜ**: 投稿ジョブの画像は VPS ローカルのパスで持っている。あなたのブラウザからは開けない。
`OPENQLOW_PUBLIC_MEDIA_DIR` と `OPENQLOW_PUBLIC_MEDIA_BASE_URL` が入って初めて、
`browser:jobs` が画像を**公開HTTPS URL**に変換して渡せる。ここが未設定だと全部テキスト投稿になる。

### T1-1. 現状確認

```bash
cd /opt/openqlow
grep -E "OPENQLOW_PUBLIC_MEDIA" /etc/openqlow/openqlow.env
npm run browser:jobs
```

`⚠️ ... 公開URLに解決できません` が出たら未設定。出なければ T1 は完了、T2 へ。

### T1-2. nginx が `/var/www/openqlow-media` を配信しているか確認

配信していなければ、既存の nginx 設定に**追記のみ**で足す（既存の location を壊さない）:

```nginx
location /openqlow/media/ {
    alias /var/www/openqlow-media/;
    autoindex off;
}
```

`nginx -t` で構文確認してから `systemctl reload nginx`。

### T1-3. env に2行を入れる

`/etc/openqlow/openqlow.env` の該当行のコメントを外し、実ドメインに直す:

```
OPENQLOW_PUBLIC_MEDIA_DIR=/var/www/openqlow-media
OPENQLOW_PUBLIC_MEDIA_BASE_URL=https://<実ドメイン>/openqlow/media/
```

反映:

```bash
systemctl restart openqlow-webhook
```

### T1-4. 通ったことを確認

```bash
cd /opt/openqlow && npm run browser:jobs
```

**完了条件**: `画像:` の行に `https://` で始まるURLが出て、警告が消えていること。
そのURLをブラウザで開いて**画像が実際に表示される**ことまで確認する。

## T2【本命】3つの投稿先に実際に投稿する

`npm run browser:jobs -- --json` で出た**未投稿ジョブを1件ずつ**処理する。

各ジョブについて:

1. `url` を開く（`threads` → threads.net / `google_business` → business.google.com / `line_voom` → manager.line.biz）
2. ログインが必要なら **止まって、何のログインが必要かを報告する**（勝手に認証情報を入れない）
3. `text` を**一字も変えずに**本文へ貼る（末尾の多言語フッターも消さない）
4. `mediaUrls` の画像をダウンロードして添付する
5. プレビューを見て、本文と画像が意図通りか確認する
6. 投稿する
7. 結果を書き戻す:

```bash
cd /opt/openqlow
npm run browser:done -- <recordId> <destination> <投稿後のURL>
```

投稿できなかった場合は必ず理由付きで記録する（黙って飛ばさない）:

```bash
npm run browser:done -- <recordId> <destination> --error "ログインを求められた"
```

**完了条件**: `npm run browser:jobs` が「ブラウザ投稿待ちはありません。」になり、
かつ3つの投稿先の画面上で投稿が実際に見えること。

## T3【任意・できれば】Threads をブラウザからAPIに格上げする

Threads だけは API 経路のコードが完成済みで、**トークンが無いためブラウザに退避している**。
トークンが入れば以後は Instagram と同じく全自動になる（＝毎回のブラウザ作業が消える）。

1. Meta の開発者画面で **Generate Threads Access Token** を実行して認可する
2. 取得したトークンを長命化する
3. `/etc/openqlow/openqlow.env` に入れる:
   ```
   THREADS_USER_ID=<数字のID>
   THREADS_ACCESS_TOKEN=<長命トークン>
   ```
4. 検証する:
   ```bash
   cd /opt/openqlow && npm run threads:check
   ```
   `✅ Threadsトークン有効` が出れば成功。`THREADS_USER_ID` がずれていれば警告が正しい値を教えてくれる。
5. `systemctl restart openqlow-webhook`

**この手順は本人の認可操作を含む。JIN本人の同意のもとで行い、認可画面が出たら本人に渡すこと。**

## 絶対に守ること

- **実際に投稿できていないのに `browser:done` を成功として実行しない。** ここが崩れると全部が嘘になる。
- 本文を書き換えない。直したいときは LINE の修正フローで直してから出す。
- Cookie・トークン・パスワードを読み出さない、保存しない、ログや報告に書かない。
- `.env` の中身を git に入れない。commit 前に `git diff` で必ず確認する。
- Instagram の API 経路には触らない（すでに動いている）。
- 二重投稿しない。`browser:jobs` に出てこないジョブは完了済み。
