## 0. 使い方

- **実装の前に読む。** 各Phaseは、ここにあるテストを全部合格して初めて「完了」です。
- 印の意味：
  - **[自動]** コードのテストで確かめる（OBSの代わりに偽物＝Fakeを使う。実機不要）
  - **[実機]** 本物のOBS・iPhone・YouTubeで確かめる
  - **[人]** 人が操作して確かめる
- [実機] [人] を確かめていないときは「実機未確認」と報告し、合格に数えない（AGENTS.md §6）。
- テストデータは架空の名前だけ（AGENTS.md R8）。

## 3. 小学生UIテスト

- **誰が**：Event OSを初めて見る協力者（スタッフ・中学生など）。事前説明は「画面の『次』を読んで押してね」の1文だけ。
- **何を**：練習モード・架空データで模擬3試合（休憩1回を含む）。
- **記録**：迷って止まった回数、間違えた進行の回数、聞かれた質問。
- **合格**：
  - 迷って止まるのは1試合あたり1回以下
  - 間違えた進行は0回（間違えても ↩戻る で自分で直せたら0回と数える）
  - 終わった後に「次に何を押せばいいか分かった」と答える

## 4. CHAOS シナリオ（AT-P6）

共通の合格基準：**試合進行が止まらない／Mac内の録画が残る／画面が正直な状態を出す（確かめていないのに ✅ を出さない）。**

| ID | 起こし方 | 期待する動き | 合格基準 |
|---|---|---|---|
| C1 | サブカメラを抜く | 自動でメインへ。画面に知らせる | 「映っていない」と判定してから1秒以内に切替 |
| C2 | メインカメラを抜く | ❌を最優先表示。サブが映っていればサブを表示 | 同上 |
| C3 | インターネットを切る（ルーターの外向きの線を抜く） | 進行・場面切替・録画は続く。配信ランプが変わる | 進行操作が全部できる |
| C4 | OBSを強制終了して再起動 | ⚠️未確認 → 再接続。録画が止まっていたら最優先で「● 録画を始める」 | 起動完了から10秒以内に再接続 |
| C5 | 操作中のiPadのWi-Fiを切る／画面を再読み込み | Macの画面で同じ状態から続けられる | 3秒以内に同じ状態 |
| C6 | Event OSを強制終了して再起動 | 停止中もOBSの映像・録画は続く。再起動で状態が戻る。手動モード中なら場面を勝手に変えない | 状態が記録と一致 |
| C7 | OBSを固まらせる（応答なし） | 命令は打ち切り ⚠️。画面は固まらない | 画面操作が止まらない |
| C8 | 録画先の空きを減らす | 足りなくなる前に ⚠️、足りなければ ❌ | 録画が止まる前に知らせる |
| C9 | Macの電源ケーブルを抜く | 電池で動いていることを ⚠️ で知らせる（推奨項目） | 知らせが出る |
| C10 | 配信を長時間止める（回線断が続く） | 録画は続く。配信の再開は運営モードで人が判断 | 自動で配信を始め直さない |

- 擬似故障（ソフト）は管理モードかつ練習モードの時だけ使える。本番中は使えない。
- 実機の故障（ケーブルを抜く等）も、本番前のリハーサルで最低1回ずつ行う。

## 5. 完了の定義（全Phase共通）

1. そのPhaseの [自動] がすべて合格。
2. [実機] [人] は実施結果を記録（未実施は「実機未確認」と明記し、合格に数えない）。
3. AT-ALL がすべて合格。
4. Codexのセカンドレビューで指摘が残っていない。
5. 完了報告（AGENTS.md §6 の型）を出し、JINが承認。
