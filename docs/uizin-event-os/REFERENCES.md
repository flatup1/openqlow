## 0. 結論：借りる・設定で済ます・作る

| 部品 | 判定 | 理由 |
|---|---|---|
| 映像の合成・録画・配信 | **借りる**（OBS Studio） | 無料・定番。録画と配信が別の出力で、配信が落ちても録画は続く［確認済み］ |
| OBS の遠隔操作 | **借りる**（OBS 標準の obs-websocket v5） | OBS 28 以上に最初から入っている。追加インストール不要［確認済み］ |
| obs-websocket の通信部品 | **小さく作る**（約200行） | 既存ライブラリ obs-websocket-js（MIT・5.0.8）は「応答待ちに時間切れが無い」「切断時に待ちが終わらない」「自動再接続なし」［確認済み］。どうせ包む必要があり、包むより作る方が小さい。Node 22 標準の WebSocket だけで動き、`npm install` も版の管理も不要 |
| 進行・次の一手・やさしい画面 | **作る** | これが UIZIN Event OS の価値そのもの。既製品が無い |
| 予備の操作盤 | **借りる（任意）**（Bitfocus Companion） | MIT。Event OS が止まっても OBS を直接操作できる。ただし大会の進行ロジックは置かない |
| YouTube の配信枠 | **設定で済ます**（YouTube Studio で人が作る） | API 連携は OAuth と第2の秘密が増えるだけ。使い回せる配信キー1本で足りる［確認済み］ |
| 試合データ | **設定で済ます**（Sheets から CSV を手で保存） | 「ウェブに公開」は未成年の名前が誰でも見られる状態になる［おそらく］ |
| カメラアプリ | **借りる**（macOS 標準の連係カメラ、または Moblin） | 無料。§3 |
| DJ / VJ | **後で借りる**（Phase 7 以降） | 入場曲だけなら OBS のメディア部品で足りる［確認済み］。DJ/VJ は OSC/MIDI の対応表方式で後付け |

## 2. OBS と obs-websocket（Phase 1〜6 の土台）

| 事実 | 印 | Event OS での使い方 |
|---|---|---|
| obs-websocket は OBS 28.0.0 以上に同梱。初期ポートは 4455 | 確認済み | 接続先の既定値 `ws://127.0.0.1:4455` |
| **最初は「WebSocket サーバーを有効にする」が OFF**。認証は ON が既定で、初回にパスワードを自動生成する。6文字未満は不可 | 確認済み | 手順書の最初の一歩（RUNBOOK.md）。つながらない時の文言にも入れた |
| 起動オプションで有効化はできない（`--websocket_port` 等はあるが ServerEnabled は変えない） | 確認済み | 画面の設定で1回だけ ON にする |
| 待ち受けはすべてのネットワーク（localhost だけにする設定は無い） | 確認済み | 認証は必ず ON。会場の共用 Wi-Fi に Mac をつながない |
| 認証は `secret = base64(SHA256(パスワード+salt))`、`auth = base64(SHA256(secret+challenge))` | 確認済み | `src/obs/protocol.mjs` |
| 切断コード 4009 = パスワード違い、4011 = OBS 側で切られた（**自動で再接続してはいけない**） | 確認済み | どちらも再接続を止め、やさしい言葉で知らせる |
| 状態コード 207（準備中）は「少し待ってやり直してよい」 | 確認済み | 失敗扱いにせず、次の見回りで合わせ直す |
| 命令名：SetCurrentProgramScene / GetSceneList / StartRecord / StopRecord / GetRecordStatus / StartStream / StopStream / GetStreamStatus / SetInputSettings / SetInputMute / GetStats / GetVersion / CreateRecordChapter ほか | 確認済み | `src/obs/allowlist.mjs`（Phase ごとの許可リスト） |
| **GetStreamServiceSettings は配信キーを平文で返す** | 確認済み | どの Phase でも使わない（許可リストの「禁止」に入れ、テストで固定） |
| 通知：CurrentProgramSceneChanged / RecordStateChanged / StreamStateChanged（RECONNECTING・RECONNECTED あり）/ RecordFileChanged / ExitStarted。音量メーター（50ms ごと）は明示的に購読したときだけ | 確認済み | 手動モードの検知、録画・配信の見張り。音のチェックの3秒だけメーターを購読 |
| スタジオモード中でも SetCurrentProgramScene は本番画面を直接切り替える | 確認済み | スタジオモードは使わない方針（単純にするため） |
| **録画と配信は別の出力。配信が切れても録画は止まらない** | 確認済み | 「録画が主、配信が従」の土台 |
| **ただし「配信時に自動で録画」ON かつ「配信停止時も録画を続ける」OFF だと、配信を止めた瞬間に録画も止まる**（どちらも既定は OFF） | 確認済み | 開始前チェックの👤項目。配信を止めた後は必ず録画を確かめる（`afterStreamStop`） |
| 配信の自動再接続：既定 ON・2秒・最大25回。**待ち時間は約1.5倍ずつ延び最大15分**。25回で約3時間 | 確認済み | ネットが戻っても配信が長く戻らないことがある → 60秒を超えたら「配信をやり直す」を案内（自動で何度も始め直さない） |
| **Hybrid MP4（OBS 30.2 から）は落ちても壊れにくく、チャプターも入る**。OBS 32 の macOS 既定は Hybrid MOV。素の mp4/mov は落ちると録画を失う | 確認済み | 開始前チェックで mp4/mov を ❌ にする |
| CreateRecordChapter は obs-websocket 5.5.0 から。録画していないと 501、形式が対応していないと 702 | 確認済み | 試合開始ごとに「第N試合」（選手名は入れない）。702 なら以後送らない |
| チャプターは録画を正しく閉じた時だけファイルに書かれる（落ちると消える） | 確認済み | Event OS 自身の操作記録を正本にし、大会後に書き出す |
| GetStats / GetRecordStatus / GetStreamStatus の中身（outputActive・outputDuration・outputReconnecting 等） | 確認済み | 2秒ごとの見回り。outputDuration から録画の開始時刻を逆算 |
| 文字部品の SetInputSettings は既定で「上書き合成」（フォント・色は残る） | 確認済み | 文字（text）だけを書き換える。それ以外のキーは送れないようにした |
| OBS が不正終了すると、次の起動で「セーフモード（プラグイン・スクリプト・**WebSocket 無効**）で起動するか」を聞く | 確認済み | 手順書に大きく「通常モードを選ぶ」と書いた |
| 自動更新の確認は既定 ON。`--disable-updater` で止められる。32.2 系は macOS 12 で起動しない | 確認済み | 版を固定・更新は本番前に止める |
| obs-websocket-js：自動再接続なし、`call()` に時間切れなし、切断時に待っている命令が終わらない | 確認済み | 自作の小さなクライアントを選んだ理由（§0） |

## 3. カメラ（Phase 2）

| 事実 | 印 | Event OS での使い方 |
|---|---|---|
| 連係カメラ（Continuity Camera）は macOS 13・iOS 16 以上、**Mac と iPhone が同じ Apple ID**、有線（USB）または近くで Bluetooth と Wi-Fi が ON | 確認済み（Apple WWDC22） | **メインの第一候補**：ジム所有の同じ Apple ID の iPhone を USB でつなぐ |
| OBS の「映像キャプチャデバイス」で使える。抜けると映像は**凍結ではなく空白**になり、同じ端末を挿し直すと自動で戻る | 確認済み（OBS ソース） | 「真っ黒が続いたら映っていない」の判定に使える |
| 1台の Mac で連係カメラの iPhone を2台同時に使えるか | 未確認 | 実機で確かめる（ROADMAP 未決事項） |
| Moblin（MIT・無料・時間制限なし）は SRT/RTMP 等で送れる。**アプリが裏に回ると映像は静止画になる** | 確認済み | **サブの第一候補**。止まった絵の検知が必須（実装済み） |
| OBS のメディア部品で `srt://0.0.0.0:<port>?mode=listener` を待ち受けられる（OBS の FFmpeg は SRT 入り） | 確認済み | 会場専用ルーター上ならインターネット不要 |
| **メディア部品の「アクティブになったら再生し直す」が ON（既定）だと、サブが画面に出ていない間は待ち受けを止める**（SRT は自動で OFF にならない） | 確認済み | 手順書で OFF を必須にした |
| VDO.Ninja は AGPL-3.0。**開始にはインターネット（接続仲介サーバー）が必要**。無料のホスト型サービスに保証は無い | 確認済み | 予備扱い。メインには使わない |
| 無料版 Larix は 30分＋30分で配信が止まる | おそらく | 使わない（使うなら有料版＝人の承認が要る） |
| NDI（DistroAV）は無線での利用を公式が推奨していない。部品が多い | 確認済み | Phase 2 では使わない |
| GetSourceScreenshot は**幅と高さを両方**指定する（片方だけだと映像が無い時の結果が不定）。画面に出ていない部品も撮れる | 確認済み（コード読み） | 32×18 の BMP で2秒ごとに判定（`src/obs/frame_check.mjs`） |
| GetSourceActive は「画面に出ているか」だけで、カメラの生死は分からない | 確認済み | 使わない |
| iPhone は熱くなると、画面が暗くなる・充電が止まる・フレームレートが落ちる | おそらく（Apple 記事の抜粋） | 休憩ごとに熱を確認。日陰に置く。ケースを外す |

## 4. YouTube（Phase 5）

| 事実 | 印 | Event OS での使い方 |
|---|---|---|
| 初めてライブ配信を有効にすると、**使えるまで最大24時間**かかる（OBS の表示文） | 確認済み | 2週間前に有効化、1週間前に限定公開でテスト（RUNBOOK.md） |
| 初回配信には電話番号での確認が必要。過去90日に配信制限が無いこと | おそらく | 同上 |
| 使い回せる配信キー（isReusable）を1本作れば、毎回 OBS を設定し直さなくてよい。OBS の「新しい配信枠を作成」は使い捨てのキーを作る | 確認済み | 当日は「新しい配信枠を作成」を押さない |
| 公開範囲は 公開 / 限定公開 / 非公開 | 確認済み | 練習は限定公開。公開範囲は JIN が決める（👤） |
| **自動停止 ON だと、回線が約1分切れただけで配信枠が終わる**（家族に送った URL が使えなくなる） | おそらく | 自動停止は OFF を推奨（👤チェック） |
| 遅延は「通常」を推奨（字幕・高画質に対応、視聴が途切れにくい） | おそらく | 大会は双方向のやり取りが不要 |
| 12時間を超える配信は自動でアーカイブされないことがある | おそらく | 長い日は午前・午後で配信枠を分ける |
| **ライブ配信は第三者の著作物を自動で検出し、差し替え・中断・停止がありうる。許可があっても止まることがある** | おそらく | 市販の入場曲は配信に乗せないを原則に |
| 著作権で配信が削除されると、警告（ストライク）と**7日間の配信制限** | おそらく | 1曲の事故でジムのチャンネルが1週間配信できなくなる → 入場曲の扱いを「必須の👤チェック」にした |
| JASRAC・NexTone と YouTube の契約は「作詞作曲」の権利。**市販 CD・配信音源の「原盤（レコード会社の権利）」は別に許可が要る** | おそらく | 法的判断はしない。最終確認は JIN（必要なら専門家） |
| 未成年が映る動画は、コメント・ライブチャット等が自動で制限されることがある | おそらく | ライブチャットを前提にしない |
| 「子ども向け」かどうかの申告はチャンネル運営者の法的な申告（YouTube が上書きすることもある） | おそらく（API 定義は確認済み） | Event OS は決めない。JIN の👤チェック |
| YouTube Live API の書き込みは OAuth（youtube / youtube.force-ssl）が必要 | 確認済み | Phase 5 では使わない |

## 5. 音声・DJ・VJ・予備の操作盤

| 事実 | 印 | Event OS での使い方 |
|---|---|---|
| OBS の音声トラックは6本。配信に乗るのは1本だけ（詳細出力モードで選ぶ）。録画は複数トラックを同時に残せる | 確認済み | 「録画には全部、配信には MC＋会場音だけ」は OBS の設定でできる |
| 各音源は「モニターのみ（出力はミュート）」にでき、配信にも録画にも乗らない。モニター先の機器は OBS 全体で1つだけ | 確認済み | 入場曲を会場スピーカーだけに流す方法の候補（Phase 7） |
| **会場スピーカーの音は、会場マイク・カメラのマイクから空気を通って入る**（トラックを分けても防げない） | おそらく（物理的な事実） | **入場中は会場マイクをミュートする機能を実装**（`audio.muteDuringEntrance`。既定は空＝何もしない） |
| OBS の音声は「本番画面に映っている部品」からだけ混ぜる | 確認済み | 入場曲の部品を入場シーンだけに置くと、場面を変えた瞬間に止まる。置き方に注意 |

| macOS 13 以上なら OBS 標準でアプリの音を取り込める | 確認済み | 仮想オーディオ（BlackHole 等）は予備だけ |
| Companion の HTTP API（既定ポート 8000）はボタンを押す・変数を書くことができる。**本当の認証は無く、すべてのネットワークで待ち受ける** | 確認済み | 使うなら localhost か閉じた LAN だけ |
| companion-module-obs-studio の v4 はまだベータ（Companion 5.0 以上・OBS 32.1 以上を推奨） | 確認済み | 安定版の組み合わせを1つに固定 |
| Mixxx は GPL-2.0 以上。MIDI/HID で操作。ネットワーク経由の操作口は見当たらない | おそらく | DJ Adapter は「仮想 MIDI＋対応表」で後付け |
| Resolume は OSC（既定 7000）と REST（設定で有効化）で操作できる。有料 | 確認済み（Companion モジュール経由）／料金はおそらく | VJ Adapter は「OSC 送信＋対応表」で汎用に |

## 8. 本番前に人が公式ページで確かめること（「おそらく」の一覧）

この調査環境からは support.google.com・developers.google.com・jasrac.or.jp・nex-tone.co.jp・riaj.or.jp・support.apple.com・softvelum.com が読めなかった。次は抜粋での確認なので、JIN（または担当者）が公式ページで確かめる。

1. YouTube：初回配信の条件（電話確認・90日）、自動停止の挙動、12時間の上限、著作権の自動検出とストライク・配信制限の日数、未成年が映る動画の制限、「子ども向け」の判断基準
