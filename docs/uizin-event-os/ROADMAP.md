## 0. 結論

- **1回の指示 = 1 Phase。** 各Phaseは「作るもの」「作らないもの」「完了条件」を固定し、完了条件を満たすまで次へ進まない。
- **ソフトは無料、信頼性が要る物理部分だけ最小限買う。** PoCは0円でできる。本番品質は電源・回線・ケーブル・予備機・音声入力のどこかに少額投資した方が結果的に安い（§4）。
- 現在地（2026-10-01）：**JIN の「一気通貫で作ってよし」を受け、Phase 1〜6 のソフト部分を実装した。自動テストは合格。実機（OBS・iPhone・YouTube）での確認は未実施。** 本番の大会で使うのは、RUNBOOK.md のリハーサル（AT-P6 の実機シナリオ）を通ってから。
- Phase 0（既存UIZIN OSの凍結）は、所在が分からないため未着手のまま（Q1）。

## 2. 各Phaseの詳細

### Phase 0 — 凍結とバックアップ（0円）

- **目的**：今あるものを壊さない土台を作る。
- **やること**
  1. 既存UIZIN OSの所在を確認する。※このリポジトリ（`flatup1/openqlow`）とアクセスできるGitHubリポジトリには見当たらない（2026-10-01確認）。**JINのMac内にあるなら、場所を教えてほしい。**
  2. 既存UIZIN OSを丸ごとバックアップ（zip＋日付）し、以後は大きな書き換えを禁止（freeze）する。
  3. 棚卸し表を作る：何ができるか／どの画面か／何につながっているか／使っているOBSのバージョン。
  4. OBSのバージョンを記録し、本番前の自動更新を止める。
  5. YouTubeのライブ配信機能を有効化しておく（初回は使えるまで時間がかかることがある。REFERENCES.md）。
- **作らないもの**：コード全部。
- **完了条件**：バックアップの保存先と棚卸し表がある。
- **人間承認**：既存UIZIN OSの凍結範囲。

### Phase 1 — OBS Adapter（0円）

- **目的**：Event OS から OBS の場面を切り替えられる、だけ。
- **作る**：OBS への接続・自動再接続・場面切替・手動操作の検知・状態ランプ・テスト用の最小ボタン画面（5場面のボタン）。
- **作らない**：配信の開始/停止、録画の停止、テロップ、カメラ制御、試合データ、かんたんモード画面。
- **完了条件**：ACCEPTANCE_TESTS.md AT-P1 全合格（自動テスト＋実機OBS）。
- **人間承認**：Phase 1 着手、追加する依存（REFERENCES.md の OBS接続ライブラリ）、実装場所 `tools/uizin-event-os/`。

### Phase 2 — iPhone 2台（0円〜）

- **目的**：メイン・サブの2台で映し、サブが落ちても自動でメインに戻る。
- **作る**：カメラのつなぎ方の手順書、サブの生死判定、サブ → メイン自動退避、📹切替ボタン。
- **作らない**：3台目、カメラアプリ、画質調整機能。
- **完了条件**：AT-P2 全合格。特に「サブのケーブル/Wi-Fiを抜いたらメインに戻る」。
- **人間承認**：つなぎ方（有線/無線）の選択、ケーブル等の購入。

### Phase 3 — シーン5個と🛟安全運転（0円）

- **目的**：場面の型を5つに固定し、迷ったら戻れる場所（SAFE）を作る。
- **作る**：シーン一式の作り方（名前の決まり）、シーン一式の書き出しファイル（秘密情報なし）、🛟安全運転／通常に戻す。
- **作らない**：6個目以降のシーン、凝った演出。
- **完了条件**：AT-P3 全合格。

### Phase 4A — 進行と NEXT ACTION（0円）

- **目的**：スタッフが「今・次・実行」だけで1試合を回せる。
- **作る**：試合データの読込（大会前にMacへ保存）、試合の状態（EVENT_OS_SPEC.md §4）、NEXT ACTION、かんたんモード画面、↩戻る、操作記録、配信NGの扱い。
- **作らない**：テロップ（4B）、運営/管理モードの全機能（必要な最小限だけ）。
- **完了条件**：AT-P4A 全合格＋小学生UIテスト（模擬3試合）。

### Phase 4B — テロップの一元化（0円）

- **目的**：試合データ → Event OS → OBSテロップ。当日の手打ちをゼロにする。
- **作る**：決められた名前のOBS文字部品へ、表示名を流し込む。
- **作らない**：テロップのデザイン（OBS側で作る）。
- **完了条件**：AT-P4B 全合格。

### Phase 5 — 練習モードと限定公開テスト（0円）

- **目的**：配信せずに本番データで練習でき、YouTube限定公開で30〜60分流しても落ちない。
- **作る**：練習モード（EVENT_OS_SPEC.md §8）、配信の開始/終了（運営モード・長押し＋確認）、配信のPRE-FLIGHT項目。
- **作らない**：YouTubeの管理API連携（配信枠の作成は人がYouTube Studioで行う）。
- **完了条件**：AT-P5 全合格。限定公開の録画とMac内の録画が両方残る。
- **人間承認**：限定公開テストの実施、配信設定。

### Phase 6 — わざと壊す（0円〜）

- **目的**：本番で起きる故障を、本番前に全部起こして戻せることを確かめる。
- **作る**：擬似故障の切替（管理＋練習モード限定）、PRE-FLIGHT の残り項目。
- **完了条件**：AT-P6 のシナリオ全部で、合格基準の時間内に戻せる。
- **人間承認**：本番投入（ここを通るまで本番の大会では使わない）。

### Phase 7 — DJ / VJ / 音声（安定後）

- Phase 6 合格後、1つずつ足す。順番の案：**音声（入場曲を配信に乗せない）→ DJ → VJ**。
- 1 Adapter = 1 Phase。先に REFERENCES.md で「借りられるか」を判定する。

### Phase 8 — テンプレートと横展開

- 自社大会で2回無事故になってから。EVENT_OS_SPEC.md §13・§15。

## 4. 費用の考え方

- **ソフトは全部無料で始める**：OBS Studio、OBS標準のリモート操作機能、Node.js、Google Sheets、YouTube。
- **少額投資した方が安いもの（Phase 2・6で判断）**：
  - 有線接続のケーブル・変換アダプタ（メインカメラ用）
  - 会場内だけの専用ルーター（会場Wi-Fiに頼らない）
  - 電源タップ・延長コード、できれば小型の無停電電源
  - 音響ミキサーからMacへの音声入力
  - 予備のiPhone充電手段
- 金額は機材を決めるときにJINが判断する（ここでは決めない）。
