# UIZIN Event OS — 構成（ARCHITECTURE）

最終更新: 2026-10-01 / 起案: Claude / 承認: 未（オーナー承認前）
実装: `tools/uizin-event-os/`（Phase 1〜6 のソフト部分。実機テストは未実施）

---

## 0. 結論

- Event OS は **薄い司令塔（Thin Orchestrator）**。持つのは「大会の状態」「次の一手」「あるべき姿（OBSがどうなっているべきか）」の3つだけ。
- 外の機械とは **Adapter** だけが話す。Adapter が壊れても、状態エンジンと画面は止まらない。
- 命令は「この場面にして」ではなく **「今あるべき姿」を渡して、Adapter が合わせる（reconcile）** 方式。OBS が再起動しても、つながり直した瞬間に正しい姿へ戻せる。
- 人が OBS を直接触ったら、Event OS は **自動で上書きするのをやめる（手動モード）**。
- 全操作を **追記だけの記録** に残し、そこから状態を組み立て直す。落ちても再起動で元に戻り、大会後はチャプターや切り抜き区間に再利用できる。
- **インターネットを使わない。** Event OS と OBS は同じ Mac の中で話す。ネットが要るのは OBS → YouTube だけ。

## 1. 全体図

```text
              UIZIN EVENT OS（Mac上の小さなサーバー1つ・Node.js 22・依存ゼロ）
       ┌──────── やさしい画面（ブラウザ） ────────┐
       │     今 ／ 次 ／ 実行   （iPad・iPhone・Mac）  │
       └───────────────────────────┘
                        ↓ 押した（版番号つき）
                EVENT STATE ENGINE（純ロジック）
          状態 ＝ 操作記録を先頭から積み上げたもの
                        ↓
                あるべき姿（Desired）を計算
                        ↓
                    COMMAND BUS
                        ↓
 ┌──────────┬──────────┬──────────┐
 │ OBS      │ AUDIO    │ SHEETS   │   ← 実装済みは OBS（音声のミュートを含む）
 │ Adapter  │（OBS経由）│（CSV読込）│
 ├──────────┼──────────┼──────────┤
 │ DJ       │ VJ       │ YouTube  │   ← Phase 7 以降。YouTube は人が操作
 │ Adapter  │ Adapter  │（作らない）│
 └──────────┴──────────┴──────────┘
```

- OBS は OBS、DJ は DJソフト、VJ は VJソフト、YouTube は YouTube。Event OS は「今何をすべきか」だけ判断する。
- YouTube は Adapter を作らず、OBS の配信機能と YouTube Studio を人が使う（REFERENCES.md §4）。

## 3. 状態の持ち方（操作記録から組み立てる）

### 3.1 操作記録（1行1操作）

```json
{"seq":12,"at":"2026-11-03T04:05:12.345Z","type":"ENTRANCE","corner":"red","bout":3,"rev":11,"by":"ipad-1","role":"easy"}
```

- `seq` は連番、`rev` は進行を変える操作の版番号（増えるだけ）。時刻は UTC。
- 「↩戻る」も1行の操作（`UNDO`）として足す。取り消された行は消さず、組み立ての時に飛ばす。
- OBS で起きたこと（録画・配信の開始/停止、手動操作）も `OBS_*` として同じ記録に残す（大会後の書き出しに使う）。
- 本番（`live.jsonl`）と練習（`rehearsal.jsonl`）は別ファイル。
- 保存先はリポジトリの外（既定 `~/UIZIN-EventOS/data/`）。リポジトリの中を指定すると起動しない。1件ずつ fsync し、書き途中で落ちた最後の1行だけは読み飛ばす。

### 3.2 二重操作を防ぐ

- 画面は押したとき、自分が見ていた版番号（`expectedRev`）を一緒に送る。
- サーバーは今の版番号と違えば **受け付けず**「画面を更新しました」と返す。判定と記録の間に待ちを挟まないので、2台同時押しでも1回分だけ進む。
- 画面側でも、押した直後の1秒はボタンを押せなくする。
- カメラ・🛟 は版番号を見ない（同じ指示は何もしない＝何度押しても安全）。

### 3.3 落ちても戻る

- 再起動すると、操作記録を先頭から読み直して同じ状態を作る（テストで固定）。
- 画面はサーバーからの通知（SSE）で「変わった」を受け取り、最新の状態を取り直す。ブラウザが自動でつなぎ直すので、再読み込みしても同じ状態に戻る。

## 4. Adapter の約束（契約）

1. **失敗を外に投げない。** 例外で状態エンジンや画面を止めない（`tryReq`）。
2. **時間を区切る。** 応答が無ければ3秒で打ち切る。切断したら、待っている命令はすべて失敗として終わらせる（待ちっぱなしにしない）。
3. **確かめていないのに ok と言わない。** 最後に確かめてから時間がたったら `unknown`（`src/core/health.mjs`）。
4. **偽物（Fake）を必ず用意する。** `src/obs/fake_obs.mjs` は本物と同じ手順で話す偽物の OBS。自動テスト・体験モード・わざと壊す練習で使う。
5. **送ってよい命令は Phase ごとの許可リストだけ**（§5.3）。中身も確かめる（テロップは文字だけ、ミュートは設定した入力だけ、表示切替は CAM シーンだけ）。

## 5. OBS Adapter（Phase 1）

### 5.1 つなぎ方

- OBS 標準のリモート操作機能（obs-websocket v5）。**最初は OFF** なので、OBS の「ツール → WebSocket サーバー設定」で1回だけ ON にする（起動オプションでは ON にできない）。初期ポート 4455、認証は ON のまま。
- 接続先は設定ファイル、パスワードは `secrets.env` か環境変数だけ。画面・記録・エラー文に出さない（テストで固定）。
- つながらなければ、1秒・2秒・4秒…最大10秒の間隔でつなぎ直し続ける。ただし **パスワード違い（4009）と OBS 側で切られた（4011）は止めて知らせる**（4011 は公式に「自動で再接続してはいけない」）。
- 通信部品は自作（約200行・Node 22 標準の WebSocket）。理由は REFERENCES.md §0。

### 5.2 あるべき姿に合わせる（reconcile）と手動モード

```text
あるべき姿 = 状態（試合の段階）＋ 🛟安全運転か ＋ カメラの選択 ＋ 配信しない試合か
             → { 番組の場面, サブを見せるか, テロップの中身, 入場中のミュート }

OBS Adapter:
  あるべき姿が変わった／つながり直した → OBS の今の姿と比べて、違う所だけ命令する
  OBS から「場面が変わった」通知 → 自分が5秒以内に出した命令の結果か？
       はい → 何もしない
       いいえ（人が OBS で変えた）→ ✋手動モード：場面とカメラの自動合わせを止める
                                     （テロップと音声のミュートは続ける）
  「🔁 自動に戻す」または「🛟 安全運転」→ 手動モードを解いて、あるべき姿に合わせ直す
```

- **大会の途中で Event OS を起動し直したとき**、OBS が予定と違う場面なら、勝手に変えず手動モードで知らせる（止まっている間に人が操作した可能性があるため）。準備中に起動したときは、そのまま合わせる。
- **OBS が落ちて起動し直したとき**（Event OS は動き続けていた）は、手動モードでなければ、つながった瞬間に正しい場面へ戻す。
- 命令が届かなかったときに備え、2秒ごとの見回りでずれていれば合わせ直す（手動モード中は除く）。
- OBS の「スタジオモード」は使わない。予備の操作盤（Companion 等）で場面を変えた場合も手動モードになる。人が触った操作が常に勝つ。

### 5.3 Phase ごとの許可リスト（`src/obs/allowlist.mjs`）

| Phase | 足す命令（obs-websocket の正式名） | 目的 |
|---|---|---|
| 1 | `GetVersion` `GetSceneList` `GetCurrentProgramScene` `SetCurrentProgramScene` `GetRecordStatus` `GetStreamStatus` `GetRecordDirectory` `GetStats` | 場面の切替と、読み取りだけの状態確認 |
| 2 | `GetSceneItemList` `SetSceneItemEnabled` `GetSourceScreenshot` | サブの表示/非表示、カメラの生死判定 |
| 3 | `StartRecord` `GetProfileParameter` | 🛟 と大会開始で録画を始める（止める命令は無い）、録画形式の確認 |
| 4 | `GetInputList` `SetInputSettings` `CreateRecordChapter` | テロップの中身、試合ごとのチャプター |
| 5 | `StartStream` `StopStream` `StopRecord` | 運営モードの危険操作（長押し＋確認） |
| 7 | `SetInputMute` | 入場中に会場マイクをミュート |
| 禁止 | `GetStreamServiceSettings`（配信キーを平文で返す）・`SetStreamServiceSettings`・`SetProfileParameter`・`ToggleStream`・`ToggleRecord` ほか | どの Phase でも送らない |

- 設定 `obs.phase` で上限を決められる（既定 7＝全部）。許可リストに無い命令は、通信の手前で止まる。
- コードに書かれた命令名が許可リストの中にあること、禁止の命令名がどこにも無いことを、自動テストで固定している（`test/safety.test.mjs`）。

### 5.4 見張り（2秒ごと）

| 見るもの | 方法 | 画面での出方 |
|---|---|---|
| 録画中か | `GetRecordStatus` と `RecordStateChanged` | 止まっていれば ❌ 最優先＋「● 録画を始める」 |
| 配信中か・つなぎ直し中か | `GetStreamStatus` と `StreamStateChanged` | 60秒を超えるつなぎ直しは「配信をやり直す」を案内 |
| メイン・サブが映っているか | 32×18 の BMP スクリーンショット（§6.2） | メインが映らなければ ❌、サブは自動で外す |
| 録画の空き容量 | `GetRecordDirectory` ＋ Mac のディスク情報（OBS が同じ Mac のときだけ） | 半分を切ったら ❌ |
| 録画形式 | `GetProfileParameter`（RecFormat2） | mp4 / mov なら開始前チェックで ❌ |
| OBS の終了 | `ExitStarted` | 「OBS が終了しています」 |

## 6. カメラ（Phase 2）

### 6.1 シーンの組み方（サブは「上に重ねる」）

```text
CAM（補助シーン。スタッフには見せない）
  ├─ SUB  … 上。普段は非表示。📹サブで表示
  └─ MAIN … 下。常に表示
WAIT / FIGHTER / FIGHT / WINNER … CAM をシーンとして入れる（＋テロップ）
SAFE … CAM を使わず MAIN を直接入れる（サブが絶対に出ない）
```

- サブを「隠す」だけで必ず下のメインが見える。**壊れたら、何もしなくてもメインに落ちる形** にしておく。
- カメラ切替は CAM の中の SUB の表示/非表示1か所だけ。どの場面にいても同じ操作で済む。

### 6.2 生死判定と自動退避（`src/obs/frame_check.mjs`）

- 2秒ごとに MAIN・SUB それぞれの小さなスクリーンショット（BMP・幅と高さを両方指定）を取る。画面に出ていない部品も撮れる。
- **取れない／真っ黒が2回続く → 映っていない**（ケーブルが抜けると映像は空白になる）。
- **前回とまったく同じ絵が10秒続く → 止まっている**（iPhone のアプリが裏に回ると静止画になるため）。生きているカメラは、静かな場面でもセンサーの揺らぎで少しずつ絵が変わる。
- 映っていない方から、映っている方へ **だけ** 自動で移る（サブ→メイン、メインが死んでサブが生きていればサブ）。戻すのは人（行ったり来たりを防ぐ）。自動で移ったことは記録と画面に残す。
- 🛟 安全運転中は自動切替をしない。

### 6.3 つなぎ方（推奨。実機で確定する）

| 役割 | 第一候補 | 予備 | 使わない |
|---|---|---|---|
| メイン（いちばん安定） | **連係カメラを USB で**（Mac と同じ Apple ID のジム所有 iPhone） | Moblin＋Mobcam プラグインを USB で（Apple ID 不要） | — |
| サブ（映ればうれしい） | **Moblin → SRT → OBS のメディア部品（待ち受け）**。Mac を有線でつないだ会場専用ルーター上 | VDO.Ninja（インターネットが要る） | 無料版 Larix（30分＋30分で止まる）、Wi-Fi の NDI |

- サブの SRT を受けるメディア部品は **「アクティブになったら再生し直す」を OFF**（ON のままだと、サブが画面に出ていない間は待ち受けを止める）。
- iPhone はアプリを前面に出したまま、画面ロックや別アプリへの切替をしない。給電しながら、ケースを外し、日陰に置く。
- 連係カメラ2台を1台の Mac で同時に使えるかは未確認（ROADMAP 未決事項）。

## 7. シーンとテロップ（Phase 3・4B）

| 名前 | 中身 | 使う状態 |
|---|---|---|
| `WAIT` | ロゴ・待機画面（＋CAMを小さく、は任意） | 準備中・待機・休憩・終了・配信しない試合 |
| `FIGHTER` | CAM ＋ 選手名テロップ | 入場 |
| `FIGHT` | CAM ＋ 対戦テロップ | 試合中・判定待ち |
| `WINNER` | CAM ＋ 勝者テロップ | 勝者表示 |
| `SAFE` | MAIN直接 ＋ 最低限テロップ | 🛟安全運転 |
| `CAM` | MAIN＋SUB（補助） | 他のシーンの部品 |

- テロップは OBS の **文字部品** を使い、名前を `EOS_` で始める：`EOS_BOUT_NO`（第N試合）`EOS_RED_NAME` `EOS_BLUE_NAME` `EOS_WINNER_NAME` `EOS_INFO`（次の試合・休憩中 等）。見た目は OBS で作り、Event OS は文字（text）だけ差し替える。
- **配信しない試合は、名前のテロップも空にする**（映像を隠しても名前が出ては意味がないため）。`EOS_INFO` に「この試合は配信をお休みします」。
- 名前は設定で変えられる（`config.scenes`・`config.texts`）。
- 別案（不採用）：ブラウザ部品で自作の画面をテロップにする。作るものが増え、Event OS が止まるとテロップが消える。必要になったら Phase 8 以降で再検討。
- テロップ（スコアボード）の **枠・ロゴ・位置を変えると、切り抜きツールの位置合わせのやり直しが必要**（§9）。

## 8. 音声

### 8.1 方針

- 映像より音の事故の方が配信を壊す。カメラのマイクではなく、**会場ミキサーの出力（MC・会場音）を主** にする。
- OBS の音声トラックは6本。**録画には全部、配信には「MC＋会場音」の1本だけ**、は OBS の設定でできる（詳細出力モード）。Event OS はこの配分を作らない（OBS のプロファイルが持つ）。

### 8.2 入場曲の問題（いちばん大きい配信リスク）

- 市販の入場曲が配信に乗ると、自動検出で差し替え・中断・停止、さらにジムのチャンネルが一定期間配信できなくなるおそれがある（REFERENCES.md §4）。
- **トラックを分けても、会場スピーカーの音は会場マイク・カメラのマイクから空気を通って入る。** だから「入場中は配信に乗るマイクを下げる」が必要。
- 実装済み：設定 `audio.muteDuringEntrance` に OBS の音声入力名を書くと、**赤入場〜青入場の間だけミュートし、試合開始で戻す**（既定は空＝何もしない）。OBS のミュートは録画にも効くので、録画にも会場音を残したい場合は、録画専用の入力を別に用意する。
- 開始前チェックに👤「市販の入場曲が配信に乗らないようにした」を必須で入れた（配信する日だけ）。

### 8.3 Phase 7 以降

- 入場曲を Event OS から鳴らす（OBS のメディア部品＋`TriggerMediaInputAction`）。DJ ソフトは不要。ただし OBS のモニター先は1つだけで、OBS が落ちると会場の音も止まるため、スマホ等の予備の再生機をミキサーにつないでおく。
- DJ / VJ は「OSC / MIDI の送信＋対応表」の汎用 Adapter（製品ごとのコードは書かない）。

## 9. 映像資産の再利用（切り抜きツールとの連携）

大会後、運営モードの「📦 書き出し」で、保存先の `exports/` に次を作る（`src/core/exports.mjs`）。

| ファイル | 中身 | 使い道 |
|---|---|---|
| `youtube_chapters.txt` | `00:00 オープニング`、`03:12 第1試合`…（配信の開始からの時刻） | YouTube の概要欄。**試合番号だけ。選手名は入れない**。配信しない試合は入れない。YouTube の条件（00:00始まり・3つ以上・10秒以上）を守る |
| `results.csv` | 試合番号・表示名・結果 | Google Sheets へ人が戻す（自動で書き込まない） |
| `clipper/NN/segments.json` | 切り抜きツールの区間（録画ファイルごと） | `python -m uizin_clipper render --manifest ... --video <録画>` |
| `truth.yml` | 試合中（ゴング〜ゴング）の区間 | 切り抜きツールの画像照合の精度を確かめる正解データ |

- `segments.json` は切り抜きツールの version 1 形式。`index`（1から）・`start_sec`（試合開始の6秒前）・`end_sec`（勝者を選んでから20秒後）・`core_start_sec`/`core_end_sec`（試合開始・終了）・`confidence: 1.0`・`locked: true`（後で検出し直しても上書きされない）。録画の長さを超えないように切りそろえる。
- 時刻は **OBS の録画開始** から数える（YouTube のアーカイブとは基準が違う）。録画が途中で分かれたら、ファイルごとにフォルダを分ける。
- この方法なら、Event OS で録った大会は **画像照合（スコアボード検出）が要らない**。テロップのデザインを変えても切り抜きは壊れない。
- 書き出しには選手の表示名が入るので、共有・コミットしない（`.gitignore` 済み）。

## 10. ネットワークと機材

```text
[会場専用ルーター]  ← インターネットが無くても会場内はつながる
   ├─ Mac（OBS ＋ Event OS）… できれば有線LAN
   ├─ iPad / iPhone（操作画面）… Wi-Fi
   └─ サブカメラ（Moblin の SRT）
[インターネット（会場回線 または モバイル回線）] ─ Mac → YouTube
```

- 会場の Wi-Fi（お客さんと共用）に Mac・操作端末をつながない（OBS のリモート操作はすべてのネットワークで待ち受けるため）。
- 専用ルーターが止まっても、**Mac 本体のブラウザ**（`http://localhost:8787/`）で操作を続けられる。
- iPad 等は、Mac の起動画面に出る **合言葉つき URL** を1回開けば登録される。合言葉の無い端末は何もできない。
- 運営・管理の操作は PIN が必要。5回間違えると5分受け付けない。他のページから命令を送らせない（Origin の確認・JSON だけ受付・CSP）。

## 11. 故障したときの動き

| 壊れたもの | 起きること | Event OS の動き | 人の動き |
|---|---|---|---|
| インターネット | 配信だけ止まる | 配信ランプを変える。進行・録画は続く。60秒を超えたら「配信をやり直す」を案内 | 回線を確認。やり直しは運営モードで |
| OBS | 映像・録画が止まる | ⚠️ → つなぎ直しを続ける。つながったら場面を合わせ、録画停止を最優先で知らせる | OBS を起動し直す。**セーフモードを聞かれたら通常モード** |
| OBS が固まる | 命令が返らない | 3秒で打ち切り、画面は止めない | 様子を見て OBS を起動し直す |
| Event OS | 画面が使えない | （止まっている）。OBS の映像・録画はそのまま続く。再起動で状態が戻る（大会中なら場面は勝手に変えない） | OBS を直接操作、または予備の操作盤。Event OS を起動し直す |
| 操作端末 | 押せない | 状態はサーバー側にある | 別の端末・Mac 本体で同じ画面を開く |
| メインカメラ | 映らない | ❌最優先。サブが映っていればサブへ | ケーブル・電源を確認 |
| サブカメラ | 映らない | 自動でメインへ | 余裕があれば直す |
| 録画 | 止まる | ❌最優先＋1タップで再開。配信を止めた後は必ず録画を確かめる | 「● 録画を始める」 |
| Google Sheets | 読めない | 大会中は使っていないので影響なし | — |
| Macの電源 | 電池で動く | ⚠️で知らせる（macOS のとき） | 電源をつなぐ |
| 会場ルーター | iPad等がつながらない | 状態はそのまま | Mac 本体の画面で続ける |

## 12. 技術選定（実装済み）

| 項目 | 選択 | 理由 |
|---|---|---|
| 言語・実行 | Node.js 22 ＋ JavaScript（ESM・`.mjs`） | **`npm install` も変換も不要**で、Mac で `node` 1行で動く。このリポジトリの CI と同じ版 |
| OBS接続 | 自作の小さなクライアント（`src/obs/protocol.mjs`） | REFERENCES.md §0 |
| 画面 | HTML 1枚 ＋ 素の JavaScript ＋ CSS。サーバーからの通知は SSE | 部品ライブラリを入れない。再接続はブラウザ任せ |
| サーバー | Node 標準の `http`（待ち受けだけ。外へは通信しない） | 依存を増やさない |
| 保存 | 追記だけのテキスト（JSON Lines）| DB を入れない。人が読める |
| 置き場所 | `tools/uizin-event-os/`（`tools/` はすでに VPS 同期の対象外） | uizin-clipper と同じ形 |
| テスト | `node --test`（100本・約2秒）。`npm run test:uizin-event-os` で CI の ops グループに入る | 依存ゼロ |

## 13. 決定の記録（短い ADR）

| # | 決定 | 理由 | 主な代替案（不採用） |
|---|---|---|---|
| D1 | 戦略C（Thin Event OS）＋ Companionの良い所を借りる | 最小コード・OSS最大活用・1つ壊れても全体が死なない | A 全部自作／B Companion中心 |
| D2 | 状態の正本は Event OS、映像の正本は OBS | 責任を混ぜない | OBSのシーン名から状態を推測 |
| D3 | あるべき姿を合わせる方式（reconcile） | 再接続・再起動に強い | 押したら命令を1回送るだけ |
| D4 | 人がOBSを触ったら手動モード。大会途中の再起動で場面が違っても手動モード | 自動化が人に勝たない | 自動で上書きし続ける |
| D5 | 追記だけの操作記録から状態を作る | 落ちても戻る・大会後に再利用 | 状態だけを上書き保存 |
| D6 | テロップは OBS の文字部品＋中身の差し替え | 作るものが最小、Event OSが止まっても最後の表示が残る | 自作HTMLのテロップ |
| D7 | YouTubeは Adapter を作らない | 配信枠は人が作れば足りる。API認証と上限の管理が不要 | YouTube Live API 連携 |
| D8 | Sheets は大会前に CSV で読むだけ。個人情報の列は読まない | 当日の通信・編集事故を消す・必要のない情報を持たない | 当日もリアルタイム同期／ウェブに公開 |
| D9 | 危険操作は運営モード＋長押し＋確認、かんたんには置かない | 誤操作で配信を壊さない | 全員に全ボタン |
| D10 | Phaseごとの命令許可リスト＋中身の確認 | 未承認の機能が紛れ込まない・配信キーを読まない | 何でも送れる |
| D11 | OBS 通信部品は自作（依存ゼロ） | 既存ライブラリは時間切れ・切断時の後始末が無い。会場の Mac で `npm install` が要らない | obs-websocket-js |
| D12 | 配信しない試合は、映像だけでなくテロップの名前も消す | 映像を隠しても名前が出れば意味がない | 映像だけ隠す |
| D13 | カメラは「映っていない方から映っている方へ」だけ自動。戻すのは人 | 行ったり来たりを防ぐ | 完全自動の切替 |
