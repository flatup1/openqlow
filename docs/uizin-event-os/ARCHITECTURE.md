# UIZIN Event OS — 構成（ARCHITECTURE）

最終更新: 2026-10-01 / 起案: Claude / 承認: 未（オーナー承認前）

---

## 0. 結論

- Event OS は **薄い司令塔（Thin Orchestrator）**。持つのは「大会の状態」「次の一手」「あるべき姿（OBSがどうなっているべきか）」の3つだけ。
- 外の機械とは **Adapter** だけが話す。Adapterが壊れても、状態エンジンと画面は止まらない。
- 命令は「この場面にして」ではなく **「今あるべき姿」を渡して、Adapterが合わせる（reconcile）** 方式。OBSが再起動しても、つながり直した瞬間に正しい姿へ戻せる。
- 人がOBSを直接触ったら、Event OSは **自動で上書きするのをやめる（手動モード）**。
- 全操作を **追記だけの記録** に残し、そこから状態を組み立て直す。落ちても再起動で元に戻り、大会後はチャプターや切り抜き区間に再利用できる。

## 1. 全体図

```text
              UIZIN EVENT OS（Mac上の小さなサーバー1つ）
       ┌──────── やさしい画面（ブラウザ） ────────┐
       │     今 ／ 次 ／ 実行   （iPad・iPhone・Mac）  │
       └───────────────────────────┘
                        ↓ 押した（版番号つき）
                EVENT STATE ENGINE（純ロジック）
          状態 ＝ 操作記録を先頭から積み上げたもの
                        ↓
                あるべき姿（Desired）を計算
                        ↓
                    COMMAND BUS
                        ↓
 ┌──────────┬──────────┬──────────┐
 │ OBS      │ AUDIO    │ SHEETS   │   ← Phase 1 は OBS だけ
 │ Adapter  │ Adapter  │ Adapter  │
 ├──────────┼──────────┼──────────┤
 │ DJ       │ VJ       │ YouTube  │   ← Phase 7 以降
 │ Adapter  │ Adapter  │（人が操作）│
 └──────────┴──────────┴──────────┘
```

- OBS は OBS、DJ は DJソフト、VJ は VJソフト、YouTube は YouTube。Event OS は「今何をすべきか」だけ判断する。
- YouTube は Adapter を作らず、OBSの配信機能と YouTube Studio を人が使う（REFERENCES.md の判定）。

## 2. 部品と責任

| 部品 | 責任 | 持たないもの |
|---|---|---|
| 画面（UI） | 状態を表示し、押されたボタンを版番号つきで送る | 状態（毎回サーバーからもらう） |
| 状態エンジン | 操作記録 → 今の状態、今の状態 → 次の一手・あるべき姿 | 時計・通信・ファイル（純ロジック） |
| Command Bus | あるべき姿を各Adapterへ配る。Adapterの失敗を状態エンジンへ伝えない | 判断 |
| Adapter | 外の機械へ合わせる。健康状態（✅/⚠️/❌）を報告 | 大会の状態 |
| 操作記録 | 追記だけ。書き換え・削除をしない | — |
| 試合データ | 大会前に読み込んだスナップショット（Macに保存） | 個人情報（表示名と配信可否だけ） |

## 3. 状態の持ち方（操作記録から組み立てる）

### 3.1 操作記録（1行1操作）

```json
{"seq":12,"at":"2026-11-03T13:05:12.345+09:00","rev":11,"type":"ADVANCE","bout":3,"to":"FIGHTING","by":"ipad-1","mode":"live"}
```

- `seq` は連番、`rev` はその操作が前提にした状態の版番号。
- 「↩戻る」も1行の操作として足す（消さない）。
- 本番（`live`）と練習（`rehearsal`）は別ファイル。
- 保存先はリポジトリの外（例：ユーザーのホーム配下の大会フォルダ）。追跡対象のディレクトリには書かない。

### 3.2 二重操作を防ぐ

- 画面は押したとき、自分が見ていた版番号（`rev`）を一緒に送る。
- サーバーは今の版番号と違えば **受け付けず**、最新の状態を返す（「画面を更新しました」）。
- これで、連打・2台同時押しでも2段進まない（AT-P4A-05/06）。

### 3.3 落ちても戻る

- Event OS を再起動すると、操作記録を先頭から読み直して同じ状態を作る。
- 画面はサーバーからの更新通知（SSE＝サーバーからの一方向の通知。ブラウザが自動でつなぎ直す）で状態を受け取るので、再読み込みしても同じ状態に戻る。

## 4. Adapter の約束（契約）

```ts
// 形のイメージ（Phase 1 で実装するときの約束。コードはまだ無い）
type Health = { status: "ok" | "unknown" | "error"; checkedAt: string; message: string };

interface Adapter<Desired> {
  readonly id: "obs" | "audio" | "sheets" | "dj" | "vj";
  /** あるべき姿に合わせる。失敗しても例外を外へ投げず、結果で返す */
  reconcile(desired: Desired): Promise<{ ok: boolean; message: string }>;
  /** 最後に確かめた健康状態。古くなったら "unknown" を返す */
  health(now: Date): Health;
}
```

守ること:

1. **失敗を外に投げない。** 例外で状態エンジンや画面を止めない。
2. **時間を区切る。** 応答が無ければ数秒で打ち切り、⚠️ を返す。
3. **確かめていないのに ok と言わない。** 最後に確かめてから時間がたったら `unknown`。
4. **偽物（Fake）を必ず用意する。** 自動テストと CHAOS（擬似故障）は偽物で行う。
5. **送ってよい命令は Phase ごとの許可リストだけ**（§5.3）。

## 5. OBS Adapter（Phase 1）

### 5.1 つなぎ方

- OBS に標準で入っている **リモート操作機能（obs-websocket v5）** を使う。バージョン・初期ポート・認証方式は REFERENCES.md。
- 接続先とパスワードは環境変数またはリポジトリ外の設定ファイルから読む（コミットしない・画面に出さない）。
- 切れたら自動で再接続し続ける（間隔を少しずつ空ける）。つながったら §5.2 で姿を合わせる。

### 5.2 あるべき姿に合わせる（reconcile）と手動モード

```text
あるべき姿 = 状態（試合の段階）＋ 🛟安全運転か ＋ カメラの選択 ＋ 配信NGか
             → { 番組の場面, サブを見せるか, テロップの中身 }

OBS Adapter:
  あるべき姿が変わった／つながり直した → OBSの今の姿と比べて、違う所だけ命令する
  OBSから「場面が変わった」通知 → 自分が出した命令の結果か？
       はい → 何もしない
       いいえ（人がOBSで変えた）→ ✋手動モード：場面の自動合わせを止める
  画面の「自動に戻す」→ 手動モードを解除して、あるべき姿に合わせ直す
```

- OBS の「スタジオモード」は使わない（本番画面を直接切り替える方が単純で事故が少ない）。
- 予備の操作盤（Bitfocus Companion 等）で場面を変えた場合も、同じく手動モードになる。人が触った操作が常に勝つ。

### 5.3 Phase ごとの許可リスト（送ってよい命令）

| Phase | 足す命令（obs-websocket の名前） | 目的 |
|---|---|---|
| 1 | `GetVersion` `GetSceneList` `GetCurrentProgramScene` `SetCurrentProgramScene` `GetRecordStatus` `GetStreamStatus` `GetRecordDirectory` `GetStats` | 場面の切替と、読み取りだけの状態確認 |
| 2 | `GetSceneItemList` `GetSceneItemId` `SetSceneItemEnabled` `GetSourceActive` `GetSourceScreenshot` | サブの表示/非表示、カメラの生死判定 |
| 3 | `StartRecord` | 🛟安全運転で録画を始める（止める命令は無い） |
| 4B | `SetInputSettings`（`EOS_` で始まる文字部品だけ） | テロップの中身 |
| 5 | `StartStream` `StopStream` `StopRecord` | 運営モードの危険操作（長押し＋確認） |
| 7 | 音量・ミュート・メディア再生の命令（REFERENCES.md） | 音声 Adapter |

- 許可リストに無い命令名がコードに出てきたら、自動テストで落とす（AT-P1-08）。
- 配信キーを読み出す命令（配信サービス設定の取得）は **どの Phase でも使わない**。配信設定の有無は人が確認する。

### 5.4 OBSから受け取る通知

番組の場面の変化、配信の状態の変化、録画の状態の変化、OBSの終了。正確な名前は REFERENCES.md。音量メーターのような大量の通知は、必要な Phase（5）になるまで購読しない。

## 6. カメラ（Phase 2）

### 6.1 シーンの組み方（サブは「上に重ねる」）

```text
CAM（補助シーン。スタッフには見せない）
  ├─ SUB  … 上。普段は非表示。📹サブで表示
  └─ MAIN … 下。常に表示
WAIT / FIGHTER / FIGHT / WINNER … CAM をシーンとして入れる（＋テロップ）
SAFE … CAM を使わず MAIN を直接入れる（サブが絶対に出ない）
```

- サブを「隠す」だけで必ず下のメインが見える。**壊れたら、何もしなくてもメインに落ちる形** にしておく。
- カメラ切替は CAM の中の SUB の表示/非表示1か所だけ。どの場面にいても同じ操作で済む。

### 6.2 生死判定と自動退避

- OBS から「その映像が来ているか」と、一定間隔の小さなスクリーンショットの変化（止まっていないか）で判定する（方法の根拠と限界は REFERENCES.md）。
- 映っていない方から、映っている方へ **だけ** 自動で移る。戻すのは人（行ったり来たりを防ぐ）。
- 🛟安全運転中は自動切替をしない。

### 6.3 つなぎ方

メインは有線を優先。具体的な方法の比較は REFERENCES.md（カメラ）。

## 7. シーンとテロップ（Phase 3・4B）

| 名前 | 中身 | 使う状態 |
|---|---|---|
| `WAIT` | ロゴ・待機画面（＋CAMを小さく、は任意） | 待機・休憩・配信NGの試合 |
| `FIGHTER` | CAM ＋ 選手名テロップ | 赤入場・青入場 |
| `FIGHT` | CAM ＋ 対戦テロップ | 試合中・判定待ち |
| `WINNER` | CAM ＋ 勝者テロップ | 勝者表示 |
| `SAFE` | MAIN直接 ＋ 最低限テロップ | 🛟安全運転 |
| `CAM` | MAIN＋SUB（補助） | 他のシーンの部品 |

- テロップは OBS の **文字部品** を使い、名前を `EOS_` で始める（例：`EOS_RED_NAME` `EOS_BLUE_NAME` `EOS_BOUT_NO` `EOS_WINNER_NAME` `EOS_INFO`）。見た目はOBSで作り、Event OSは中身だけ差し替える。
- シーン一式はOBSから書き出して、ひな形として保存する（配信キー・パスワードが入っていないことを自動検査。AT-P3-05）。
- 別案（不採用）：ブラウザ部品で自作の画面をテロップにする。凝った演出はできるが、作るものが増え、Event OSが止まるとテロップが消える。必要になったら Phase 8 以降で再検討。

## 10. ネットワークと機材

```text
[会場専用ルーター]  ← インターネットが無くても会場内はつながる
   ├─ Mac（OBS ＋ Event OS）… できれば有線LAN
   ├─ iPad / iPhone（操作画面）… Wi-Fi
   └─ サブカメラ（無線の場合）
[インターネット（会場回線 または モバイル回線）] ─ Mac → YouTube
```

- 会場のWi-Fi（お客さんと共用）に操作端末をつながない。
- 専用ルーターが止まっても、**Mac本体のブラウザ** で操作を続けられる（同じMac内なのでネット不要）。
- 操作の命令には、大会ごとの合言葉（Macの画面のQRで端末に渡す）を付ける。同じネットにいる他人が押せないようにするため。

## 11. 故障したときの動き

| 壊れたもの | 起きること | Event OS の動き | 人の動き |
|---|---|---|---|
| インターネット | 配信だけ止まる | 配信ランプを変える。進行・録画は続く | 回線を確認。配信の再開は運営モードで判断 |
| OBS | 映像・録画が止まる | ⚠️未確認 → 再接続を続ける。つながったら姿を合わせ、録画停止を最優先で知らせる | OBSを起動し直す |
| Event OS | 画面が使えない | （止まっている）。OBSの映像・録画はそのまま続く。再起動で状態が戻る | OBSを直接操作、または予備の操作盤。Event OSを起動し直す |
| 操作端末 | 押せない | 状態はサーバー側にある | 別の端末・Mac本体で同じ画面を開く |
| メインカメラ | 映らない | ❌最優先。サブが映っていればサブへ | ケーブル・電源を確認 |
| サブカメラ | 映らない | 自動でメインへ | 余裕があれば直す |
| Google Sheets | 読めない | 大会中は使っていないので影響なし | — |
| Macの電源 | 電池で動く | ⚠️で知らせる | 電源をつなぐ |
| 会場ルーター | iPad等がつながらない | 状態はそのまま | Mac本体の画面で続ける |

## 12. 技術選定（Phase 1 の提案。承認前）

| 項目 | 選択 | 理由 |
|---|---|---|
| 言語・実行 | Node.js 22 ＋ TypeScript（tsx） | このリポジトリと同じ。CIも同じ版 |
| OBS接続 | 既存の OBS 接続ライブラリ（REFERENCES.md、版を固定） | 通信手順を自作しない |
| 画面 | HTML 1枚 ＋ 素のJavaScript。サーバーからの通知はSSE | 部品ライブラリを入れない。再接続はブラウザ任せ |
| サーバー | Node標準の http | 依存を増やさない |
| 保存 | 追記だけのテキスト（1行1操作） | DBを入れない。人が読める |
| 置き場所 | `tools/uizin-event-os/`（独自の package.json） | uizin-clipper と同じ形。`tools/` はすでにVPS同期の対象外 |

```text
tools/uizin-event-os/           ← Phase 1 で作る（今は無い）
  README.md                     起動手順
  package.json                  依存は OBS接続ライブラリだけ（固定版）
  src/core/                     純ロジック（時計・通信・ファイル無し）
  src/adapters/obs.ts           外の機械と話すのはここだけ
  src/adapters/obs_allowlist.ts Phaseごとの許可命令
  src/adapters/fake_obs.ts      テスト・CHAOS用の偽物
  src/server/                   画面の配信・命令の受付・操作記録
  src/ui/index.html             画面
  test/
```

- ルートの `tsconfig.json` は `src/` だけを見るため、`tools/uizin-event-os/` の型検査とテストをCIに足す方法は Phase 1 の提案で決める（`scripts/` と CI は Codex 担当領域なので、JIN・Codexと調整）。
- 純ロジック（`src/core/`）は依存ゼロにして、どこでも1秒でテストできるようにする。

## 13. 決定の記録（短い ADR）

| # | 決定 | 理由 | 主な代替案（不採用） |
|---|---|---|---|
| D1 | 戦略C（Thin Event OS）＋ Companionの良い所を借りる | 最小コード・OSS最大活用・1つ壊れても全体が死なない | A 全部自作／B Companion中心 |
| D2 | 状態の正本は Event OS、映像の正本は OBS | 責任を混ぜない | OBSのシーン名から状態を推測 |
| D3 | あるべき姿を合わせる方式（reconcile） | 再接続・再起動に強い | 押したら命令を1回送るだけ |
| D4 | 人がOBSを触ったら手動モード | 自動化が人に勝たない | 自動で上書きし続ける |
| D5 | 追記だけの操作記録から状態を作る | 落ちても戻る・大会後に再利用 | 状態だけを上書き保存 |
| D6 | テロップは OBS の文字部品＋中身の差し替え | 作るものが最小、Event OSが止まっても最後の表示が残る | 自作HTMLのテロップ |
| D7 | YouTubeは Adapter を作らない | 配信枠の作成は人が行えば足りる。API認証と上限の管理が不要 | YouTube Live API 連携 |
| D8 | Sheets は大会前に読むだけ | 当日の通信・編集事故を消す | 当日もリアルタイム同期 |
| D9 | 危険操作は運営モード＋長押し＋確認、かんたんには置かない | 誤操作で配信を壊さない | 全員に全ボタン |
| D10 | Phaseごとの命令許可リスト | 未承認の機能が紛れ込まない | 何でも送れる |
