# UIZIN Event OS — 製品仕様（EVENT_OS_SPEC）

最終更新: 2026-10-01 / 起案: Claude / 承認: 未（オーナー承認前）
実装: `tools/uizin-event-os/`（この仕様の §2〜§12 を実装済み。ただし §2 の「運営：音量」「管理：接続先・パスワード・デバイス・Adapterの有効/無効・ログの画面」と §13 は未実装。実機テストは未実施）

---

## 0. 結論

**UIZIN Event OS は「イベントの難しい機械を、全部やさしい日本語にするOS」です。**

- スタッフに見せるのは **「今」「次」「実行」** の3つだけ。
- OBS・カメラ・配信・テロップ・録画は裏側で動き、スタッフは名前すら知らなくていい。
- Event OS 自身は **司令塔（状態の管理・次の一手の案内・命令の送信）** だけを持ち、映像・音・配信の処理は既存のソフトに任せる。
- ネット・配信・カメラ1台が止まっても、**試合進行とMac内の録画は止めない。**

---

## 1. 目的とやらないこと

### 1.1 目的（優先順）

1. 1人の運営スタッフが、マニュアル無しで、事故なく大会を最後まで回せる。
2. 試合の映像を **必ず** Macに残す（配信が落ちても失わない）。
3. 外注費・運営人数・ミスを減らす（最初のROIは販売収益ではなくこれ）。
4. 同じ仕組みを、次の大会・別のイベントにそのまま使い回せる。

### 1.2 やらないこと（Non-goals）

| やらないこと | 代わりに使うもの / 理由 |
|---|---|
| 映像の合成・エンコード・配信処理 | OBS Studio |
| カメラアプリ | iPhoneの既存アプリ・macOS標準機能（ROADMAP Phase 2） |
| DJ・VJソフトの機能 | 既存DJ/VJソフト（Phase 7以降にAdapterでつなぐだけ） |
| 公式記録・採点・試合タイマー | 審判・タイムキーパーの仕事。Event OSの記録は「配信と映像用のメモ」で公式記録ではない |
| 会員・保護者の個人情報管理 | openQLOW本体（`src/crm/`）の領域。Event OSは「配信してよいか」の旗だけを読む（§12） |
| SaaS化・他団体への販売 | 自社大会で実証してから判断（§15） |

## 2. 使う人と3つのモード

**操作は小学生レベル。権限は大人レベル。** 画面は1つ、見える範囲だけがモードで変わります。

| モード | 対象 | 見えるもの | 切替方法 |
|---|---|---|---|
| かんたん | 当日スタッフ（初見でもOK） | 今・次・大きいボタン、📹カメラ、🛟安全運転、↩戻る、ランプ2つ（●録画 ●配信） | 既定 |
| 運営 | 運営責任者 | かんたん＋OBS・カメラの状態、録画・配信の操作、音のチェック、開始前チェック、試合データの読込、結果の修正、表示名の手直し、試合の飛ばし・無効試合、書き出し（音量の操作は未実装） | 運営PIN（4〜8桁） |
| 管理 | 設定担当（JIN等） | 運営＋iPad用URL、本番/練習の切替、OBSへのつなぎ直し、わざと壊す練習、❌が残ったままの開始（接続先・パスワードは設定ファイルで変える。画面での設定・ログ表示は未実装） | 管理PIN（運営PINと別。当日は基本使わない） |

規則:

- かんたんモードで同時に見える **大きいボタンは最大3つ**。固定の小ボタンは「📹カメラ（メイン／サブの2つで1組）」「🛟安全運転」「↩戻る」の3種類だけ。
- 新しい機能はまず **運営/管理モードに置く**。かんたんモードに足すときは、何か1つを減らす（AGENTS.md R2）。
- かんたんモードには英語の専門用語（OBS・WebSocket・RTMP・NDI 等）を出さない（知らせの文では「映像ソフト」と言う）。

## 3. 画面（今・次・実行）

```text
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 ● 録画中   ● 配信中                 🛟
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 第12試合
 🔴 赤  SATO
        VS
 🔵 青  TANAKA

 今：🥊 試合中
 次：終わったら「試合終了」を押してください
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 [📹 メイン ✓映っています] [📹 サブ]  [↩ 戻す（試合開始）]

        [   🏁 試合終了   ]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

- 「次」は **Event OSが決めて文章で言う**。スタッフは考えなくていい（§5）。
- 色だけに頼らない。🔴🔵には必ず「赤」「青」の文字を付ける。
- ボタンを押した直後は約1秒ボタンを押せなくする（連打で2段進む事故を防ぐ）。押せない間はボタンを薄くし、押されたら「受け付けています」と出す。**🛟 安全運転だけは待たずに必ず送る**（何度押しても同じ結果のため）。
- 画面は中身が変わったときだけ作り直す（押している途中のボタンを消さない。選んでいる途中の表の選択も消さない）。
- 今映っているカメラは、色だけでなく「✓映っています」の文字で示す。🛟中はメイン、配信しない試合ではどちらにも付けない。
- 下に出る知らせ（数秒で消える）は、下のボタンへの指をじゃましない（知らせの上からでも押せる）。
- 同じ画面をiPad・iPhone・Macのどれで開いても同じ状態が出る（状態はEvent OSが1か所で持つ）。
- 画面を再読み込みしても、ブラウザを閉じても、状態は消えない。

### 3.1 ランプ（状態表示）の3段階

| 表示 | 意味 |
|---|---|
| ✅ / ● 緑 | **直近数秒以内に確かめて** 正常 |
| ⚠️ 黄「未確認」 | 確かめられていない、または情報が古い（つながっていない等） |
| ❌ 赤 | 確かめた結果、異常 |

確かめていないものを ✅ にしない（AGENTS.md R5）。例：OBSとつながっていない間、録画ランプは ❌ ではなく ⚠️「未確認」。**画面（iPad 等）が本体の Mac とつながっていない間も、ランプは ⚠️「未確認」にする**（前の「● 録画中」を出し続けない）。

## 4. 大会進行モデル（状態）

### 4.1 大会全体

```text
準備（PRE-FLIGHT） → 進行中（試合と休憩の繰り返し） → 終了
```

### 4.2 1試合の流れ

| 状態 | 今 | 次（NEXT ACTION） | 主ボタン | 他の選択肢 | OBSシーン | テロップ |
|---|---|---|---|---|---|---|
| 待機 | 第N試合 待機中 | 赤選手を入場させてください | 🔴 赤入場 | ☕ 休憩 | WAIT | 次の試合 赤 vs 青 |
| 赤入場 | 🔴 赤 入場中 | 青選手を入場させてください | 🔵 青入場 | — | FIGHTER | 赤の表示名 |
| 青入場 | 🔵 青 入場中 | 準備ができたら試合開始 | 🥊 試合開始 | — | FIGHTER | 青の表示名 |
| 試合中 | 🥊 試合中 | 終わったら試合終了 | 🏁 試合終了 | — | FIGHT | 赤 vs 青 |
| 判定待ち | 試合終了 | 勝者を選んでください | 🔴 赤の勝ち / 🔵 青の勝ち / 🤝 引き分け | （運営）無効試合・中止 | FIGHT のまま | 赤 vs 青 |
| 勝者表示 | 🏆 赤の勝ち | 次の試合へ進んでください | ▶ 次の試合へ | — | WINNER | 勝者の表示名 |
| 休憩 | ☕ 休憩中 | 休憩が終わったら再開 | ▶ 再開 | — | WAIT | 休憩中 |

- **入場の順番は設定で変えられる**（`flow.entranceOrder`。既定は赤→青）。切り抜きツールには「青コーナー紹介→赤コーナー紹介」の順が書かれており（REFERENCES.md §7）、どちらが正しいかは JIN の確認待ち（ROADMAP Q6）。青→赤にすると、上の表の「赤入場」「青入場」の行が入れ替わる。
- 最後の試合の「勝者表示」の次は「🎌 大会を終える」→ 大会終了。配信・録画は止めない（止めるのは運営モードの危険操作、§6）。
- ラウンド・インターバル・残り時間は扱わない（タイムキーパーの仕事。§1.2）。
- 📹カメラ（メイン/サブ）は「赤入場」〜「勝者表示」の間いつでも押せる。

### 4.3 戻る（Undo）

- 「↩ 戻す」は **直前の進行の1手だけ** 取り消す。記録は消さず、「取り消した」という記録を足す（後から何が起きたか分かるように）。
- カメラの切り替えと 🛟 は戻す対象ではない。そのため、**何が戻るかをボタンに出す**（例：「↩ 戻す（試合開始）」）。戻した後は「↩「試合開始」を取り消しました」と出す。
- 試合中に「試合開始」を戻す（配信の画面が入場に戻る）ときと、勝者の記録を戻すときは、確認を出してから戻す。
- かんたんモードでは「次の試合へ」より前には戻れない。勝者の付け直しは運営モードで行う。

## 5. NEXT ACTION（次の一手の案内）

この企画の中心機能です。普通のダッシュボードの代わりに、**OS自身が次に押すものを1つ示す**。

### 5.1 優先順位

1. **安全**：録画が止まっている、MAINカメラが映らない等 → 最優先で表示（例：「⚠️ 録画が止まっています。[● 録画を始める]」）
2. **進行**：§4.2 の「次」
3. **準備のお知らせ**：次の試合の入場曲が未確認、等（邪魔にならない小さな表示）

### 5.2 文章の型

```text
✅ 直前に終わったこと（例：赤の入場が終わりました）
次：〇〇してください
[ 主ボタン ]
```

- 1文は短く、ひらがな多め。「〜してください」で終える。
- 一度に案内するのは **1つだけ**。

## 6. 危険操作の守り

| 操作 | モード | 守り |
|---|---|---|
| 配信を始める | 運営 | 長押し2秒 ＋ 確認画面（「YouTubeに映ります。よいですか？」） |
| 配信を終える | 運営 | 長押し2秒 ＋ 確認画面（「配信が終わります。元に戻せません」） |
| 配信をやり直す（回線が戻ったのに配信が戻らないとき） | 運営 | 長押し2秒 ＋ 確認画面。止めたのを確かめてから始め直し、録画が続いているかも確かめる |
| ❌ が残ったまま大会を始める | 管理 | 長押し2秒 ＋ 確認画面。記録に「強制開始」と残る |
| 録画を止める | 運営 | 長押し2秒 ＋ 確認画面 |
| 試合データを読み直す（当日に直した表示名は消える。今の試合は試合番号で探し直し、無ければその試合の最初に戻る） | 運営 | ファイルを選ぶ ＋ 確認画面 |
| 結果の修正・試合の飛ばし・中止 | 運営 | 確認画面 |
| 録画を始める | かんたん | なし（止まっているより安全なので1タップ） |
| 🛟 安全運転 | かんたん | なし（何も止めない操作なので1タップ） |

かんたんモードには、配信・録画を **止める** ボタンを置かない。

## 7. PRE-FLIGHT CHECK（開始前チェック）

大会前に自動で点検し、全部そろったら「✅ 大会を始められます」と出します。

| 項目 | 確かめ方 | 必須 |
|---|---|---|
| OBSにつながる | 接続と認証 | 必須 |
| OBSのバージョン | 決めた版（`obs.expectedVersion`）と同じか | 推奨（設定したときだけ） |
| 決められたシーンがそろっている | WAIT / FIGHTER / FIGHT / WINNER / SAFE / CAM の名前があるか | 必須 |
| CAM にメインがある | CAM シーンの中に MAIN があるか | 必須 |
| テロップ部品がそろっている | `EOS_` で始まる5つの文字部品があるか | 必須 |
| メインカメラが映っている | 映像が来ていて止まっていないか | 必須 |
| サブカメラが映っている | 同上 | 推奨（無くても開始可） |
| 録画の空き容量 | `recording.minFreeGB` 以上あるか（OBS が同じ Mac のとき） | 必須 |
| 録画形式 | 落ちても壊れにくい形式か（mp4 / mov は ❌） | 必須 |
| 試合データ | 読み込み済み（読み込み時に、番号の重複・空欄・配信可否を確かめる） | 必須 |
| 配信しない試合を確認した | 配信NG・録画のみの試合数を出し、人が「確認した」を押す | 必須（👤） |
| 入場曲が決まっている | 未定・空欄の数 | 推奨 |
| 表示名がテロップに収まる | 12文字を超える名前 | 推奨 |
| 配信に乗る音が出ている | 運営モードの「音のチェック」（3秒） | 配信する日は必須（練習では推奨） |
| Macの電源 | 電源につながっているか（macOS のとき） | 推奨 |
| OBSの録画設定 | 「配信時に自動で録画」OFF（ON なら「配信停止時も録画を続ける」も ON） | 必須（👤） |
| OBSの自動更新 | OFF、本番1週間前から更新していない | 推奨（👤） |
| OBSが落ちたときの手順 | 「通常モード」を選ぶと担当者が知っている | 推奨（👤） |
| YouTube の配信テスト | このチャンネルで限定公開の配信をしたことがある | 配信する日は必須（👤） |
| YouTube の配信枠 | 公開範囲・自動停止OFF・子ども向けの申告を JIN が確認 | 配信する日は必須（👤） |
| 入場曲の扱い | 市販の入場曲が配信に乗らないようにした（会場マイクも含めて） | 配信する日は必須（👤） |

- 機械で確かめたものは ✅、人が確かめたものは 👤 と分けて表示する（混ぜない）。
- 推奨項目の ⚠️ は開始を止めない。例：「⚠️ 2選手の入場曲が未確認です」。

## 8. REHEARSAL MODE（練習モード）

- 本番の試合データのまま、**配信せずに**大会を最初から最後まで練習できる。
- 練習モードでは「配信を始める」を押せない（ボタン自体を出さない）。録画は任意。
- 画面上部に大きく「🧪 練習中（配信されません）」を出し続ける。
- 練習の記録は本番の記録と別に保存する（混ざらない）。
- スタッフ教育に使う：新人に練習モードで3試合回してもらう（ACCEPTANCE_TESTS.md の小学生UIテスト）。

---

## 9. CHAOS TEST MODE（わざと壊す練習）

- カメラ切断・ネット切断・OBS停止・画面の再読み込み・Event OS停止を、**本番前に**わざと起こして、戻せるか確かめる。
- ソフト側の擬似故障（Adapterを故障状態にする）と、実機の故障（ケーブルを抜く）の2段階で行う。
- 本番中は使えない（管理モードかつ練習モードの時だけ）。
- シナリオと合格基準は ACCEPTANCE_TESTS.md §4。

---

## 10. ONE TAP RECOVERY（🛟 安全運転）

何かおかしいと感じたら、考えずに押すボタン。

押すと:

1. OBSを **SAFE シーン**（メインカメラ＋最低限のテロップ）に切り替える。**ただし配信しない試合の間は、🛟中でもカメラを映さない（WAIT のまま）**。
2. 「✋ 手動モード」を解き、サブカメラへの自動切替を止める。
3. 録画が止まって（一時停止して）いたら始める（練習で録画しない設定なら始めない）。**配信には触らない**（止めない・始めない）。
4. 試合進行の状態はそのまま覚えている。

「✅ 通常に戻す」を押すと、今の試合の状態に合ったシーンに戻る。

## 11. カメラ・テロップ・録画・音声

### 11.1 カメラ

- **メイン優先。** メインは一番安定した接続（有線を優先）にする。サブは「映ればうれしい」。
- サブが映らなくなったら、自動でメインに戻す（ARCHITECTURE.md §6）。戻したことは画面に出す。
- 3台目は Phase 2 の合格後に検討する。

### 11.2 テロップ

- 試合データ（§12）の **表示名** だけを使う。手入力の打ち間違いを無くすため、当日の手打ちはしない。
- 文字の見た目（フォント・色・位置）はOBS側で作る。Event OSは文字の中身だけ差し替える。
- テロップのデザインを変えるときは、切り抜きツール（`tools/uizin-clipper`）の位置合わせもやり直しになる点に注意（ARCHITECTURE.md §9）。

### 11.3 録画と配信

```text
カメラ → OBS ┬→ Macに録画（主）
             └→ YouTube LIVE（従）
```

- 録画が主、配信が従。配信が落ちても録画は続く。
- 大会中は録画を止めない。休憩中も止めない（つなぎ目の事故を防ぐ）。

### 11.4 音声

- 音の事故は映像の事故より配信品質を壊す。カメラのマイクではなく、**会場の音（MC・ミキサーの出力）を主**にする。
- 目標は「会場で鳴らす音」と「配信に乗せる音」を分けられる構造。

```text
会場：MC ／ 選手入場曲 ／ BGM ／ 会場音
配信：MC ／ 会場音 ／ 配信に乗せてよいBGMだけ
```

- 市販曲の入場曲は、配信で権利の問題（自動検出による差し替え・中断、チャンネルの配信制限）が起きるおそれがあるため、配信に乗せない方針を基本にする。
- **会場スピーカーの音はマイクから空気を通って入る**ので、トラックを分けるだけでは防げない。設定した会場マイクを **入場中だけミュート** する機能を実装済み（`audio.muteDuringEntrance`）。具体的なやり方と限界は ARCHITECTURE.md §8、根拠は REFERENCES.md §4・§5。
- 法的な判断はしない。権利の最終確認は JIN（必要なら専門家）。

## 12. 試合データと、配信してよいか

### 12.1 流れ（Sheetsをリアルタイムの台帳にしない）

```text
大会前：Google Sheets → Event OSに読み込み → Macに保存（スナップショット）
大会中：Macの保存データだけで動く（ネット不要）
大会後：必要なら結果をSheetsへ戻す（人が確認してから）
```

### 12.2 列（例。値は架空）

| 試合番号 | 赤_表示名 | 赤_所属 | 赤_配信 | 青_表示名 | 青_所属 | 青_配信 | 区分 | 赤_入場曲 | 青_入場曲 |
|---|---|---|---|---|---|---|---|---|---|
| 1 | ヒカル | 架空ジムA | OK | ソラ | 架空ジムB | 録画のみ | キッズ | 未定 | 未定 |

- **表示名** はテロップ・配信に出る名前。未成年は、保護者の同意の範囲で決めた名前（下の名前だけ・リングネーム等）にする。決めるのは JIN。
- 年齢・学年・学校・連絡先・本名は **Event OSに入れない**（必要ない情報は持たない）。そうした列のある CSV は読み込みを止める。
- 配信の欄は `OK` / `録画のみ` / `NG` の3つ。それ以外の値や空欄は読み込みを止める（あいまいなまま配信しない）。
- **注意：配信・撮影の同意を記録する仕組みは、まだどこにも無い。** 今ある未成年の入会同意（`src/crm/guardian_consent.ts`）と紙の同意書には、写真・動画・配信の項目が無い（REFERENCES.md §7）。他のジムの選手は名簿にもいない。誰が・どう同意を集め・どこに残すかは JIN が決める（ROADMAP Q7）。Event OS は CSV の旗だけを読み、同意の中身は持たない。

### 12.3 配信NG・録画のみの試合

| 旗（赤と青の厳しい方） | Event OSの動き |
|---|---|
| OK | 通常どおり |
| 録画のみ | OBSは配信と録画が同じ画面のため、**配信だけ隠すことは標準機能ではできない**。Phase 1〜6 では「NG」と同じ扱いにし、録画が必要ならiPhone本体で別撮りする（ROADMAP 未決事項） |
| NG | その試合の間、カメラを映さず WAIT シーン（静止画）のまま進める。**テロップの名前も空にする**。スタッフの画面に「🔒 この試合は配信しません」と出す |

- 配信NGの扱いは、大会前のPRE-FLIGHTで件数を出し、人が確認する（§7）。

## 15. 事業化の順番（参考）

```text
自分の大会で使う → 複数大会で使う → テンプレート化 → 他団体で実証 → 必要なら商品化
```

- AV機器のサポート（「カメラが映らない」「会場Wi-Fiが遅い」）はソフト以外の問い合わせが多く、いきなりのSaaS化は危険。
- 最初の成果指標：外注費、当日の運営人数、配信・録画の事故件数、残せた試合映像の本数。
- 位置づけ：OBSやCompanionの競合ではなく、**それらを普通の人向けに翻訳する層**。
