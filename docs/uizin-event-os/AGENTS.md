# UIZIN Event OS — AI向け作業ルール

最終更新: 2026-10-01 / 起案: Claude / 承認: 未（オーナー承認前）

> このファイルは `docs/uizin-event-os/` と、将来の実装先 `tools/uizin-event-os/` だけに効く追加ルールです。
> リポジトリ直下の `AGENTS.md` / `CLAUDE.md` / `COORDINATION.md` が常に優先します。矛盾したら上位に従い、JINに報告します。

## 0. 結論（3行）

1. **作らなくて済むなら、作らない。** OBSはOBS、配信はYouTube、DJはDJソフトに任せる。Event OSは「今・次・実行」を決める司令塔だけ。
2. **1回の指示 = 1 Phase。** 指示されていないPhaseのコードは1行も書かない（例外は §0.1 の承認記録）。
3. **大会を止めない。** ネット・配信・カメラ1台が死んでも、試合進行とMac内の録画は続く設計だけを通す。

## 2. 実装前の必須手順（省略禁止）

```text
① 既存コードを調べる（このリポジトリ・tools/uizin-clipper・既存UIZIN OS）
② 似たOSSを調べる（REFERENCES.md にあるか → 無ければ探して追記を提案）
③ 作る必要があるか判定する（借りる / 設定で済む / 作る の3択）
④ 最小差分を提案する（変更ファイル・追加依存・テスト・リスク）
⑤ JINが承認したPhaseだけ実装する
```

③で「作る」を選ぶときは、**なぜ借りられないか**を1文で書きます。
「作れるから作った」は不合格です。

## 3. 絶対ルール

| # | ルール | 理由 |
|---|---|---|
| R1 | 承認されたPhase以外のファイル・機能を足さない | 機能追加が止まらない事故を防ぐ |
| R2 | かんたんモードのボタンを増やさない（増やすなら他を減らす） | 小学生UIを守る |
| R3 | 外部サービスが落ちても試合進行が止まるコードを書かない | Local First |
| R4 | 自動化には必ず手動の上書き（Override）を付ける | 自動化の誤りを人間が戻せるように |
| R5 | 「確かめていないのに ✅」を出さない。古い情報は ⚠️ 未確認 と出す | 誤った安心が一番危ない |
| R6 | 配信開始・配信停止・録画停止は、該当Phaseの承認が出るまでコードに持たない | 誤操作で大会を壊さない |
| R7 | 本番前の1週間は OBS・プラグイン・依存の更新をしない | 突然動かなくなる事故を防ぐ |
| R8 | 選手の個人情報（本名・学年・年齢・連絡先・同意書の中身）をコミットしない。テストは架空データだけ | 未成年が多い大会のため |
| R9 | パスワード・配信キー・APIキーは環境変数か手元の設定ファイル（gitignore済み）だけ | 漏れたら配信を乗っ取られる |
| R10 | `src/` 配下（openQLOW本体・AIKA・canon・LINE・publish・deploy）を変更しない | 担当領域が違う。必要なら提案だけ |
| R11 | Event OS はインターネットへ通信しない。外部 npm 依存を足さない（足すなら §2 の判定と JIN の承認） | 会場でネットが無くても動き、`npm install` も要らないため |
| R12 | OBS への新しい命令は `src/obs/allowlist.mjs` に Phase つきで足し、テストを通す。配信キーを読む命令は使わない | 許可リストで未承認の機能と秘密の漏れを防ぐ |

## 5. そのまま貼れる指示文（JIN用）

長い会話を毎回貼らないために、これだけ送れば動く形にしてあります。

### Claude Code（実装）

```text
docs/uizin-event-os/AGENTS.md と ROADMAP.md の Phase N を読み、
AGENTS.md §2 の手順①〜④を出してください。承認したら Phase N だけ実装し、
ACCEPTANCE_TESTS.md の Phase N を全部回して報告してください。
```

### Codex（レビュー）

```text
docs/uizin-event-os/AGENTS.md と ACCEPTANCE_TESTS.md の Phase N を読み、
ブランチ <branch> の差分をレビューしてください。
観点: バグ / セキュリティ / テスト不足 / Phase外の変更 / かんたんモードのボタン増加。
コードは直さず、指摘だけ返してください。
```

### ChatGPT（完成判定）

```text
添付の EVENT_OS_SPEC.md §1〜§3 と、Phase N の完了報告を読み、
「機能を増やしすぎていないか」「小学生UIを壊していないか」「大会が止まる経路がないか」
の3点だけを ○/× と理由1行で判定してください。
```

## 6. 完了報告の型

リポジトリ直下 `AGENTS.md` の順番（作成・変更・保持・検証・未実装・人間確認・Git状態）に、次の2行を足します。

```md
- 受入テスト: AT-Pn-01 〜 AT-Pn-xx のうち ○件合格 / ×件不合格 / 実機未確認 ○件
- かんたんモードのボタン数: 変更前 ○ → 変更後 ○
```

実機（OBS・iPhone・YouTube）で確かめていない項目は「実機未確認」と書き、合格扱いにしません。
