# UIZIN 大会動画 自動切り抜きシステム 設計書

最終更新: 2026-08-07 / 起案: Claude / 承認: 未（オーナー承認前）

---

## 0. 結論（先に読む部分）

**「AIで入場・ゴング・勝敗を認識して試合を切り出す」は、最初にやってはいけません。**

理由は1つです。**大会配信には、AIより正確で、無料で、壊れない信号がすでに映っている**からです。
それが **試合中だけ画面に出るスコアボード（テロップ）** です。

- スコアボードが出ている = 試合中
- 消えている = MC・休憩・表彰

これは「AIの推論」ではなく「画面の一部が一致するか」の照合なので、
**精度がほぼ100%・CPUだけで動く・無料・壊れても原因がすぐ分かる**という、
今回の優先順位（①無料 ②精度 ③自動化 ④保守性 ⑤速度）に完全に一致します。

音声（ゴング）とAI（OCR・Whisper・LLM）は、**主判定ではなく「後段の味付け」**に降格させます。
この一点だけで、システムの寿命が数年単位で伸びます。

## 1. あなたの案への反論（遠慮なく否定します）

| あなたの案 | 判定 | 理由 |
|---|---|---|
| AIで入場・ゴング・試合・勝敗を認識して分割 | ❌ 主判定としては不採用 | 学習データが必要／GPUが必要／大会ごとに演出が変わると壊れる／なぜ間違えたか説明できない。保守性が最悪。 |
| ゴング音で試合開始を検出 | △ 補助のみ採用 | 歓声・BGM・入場曲・マイクのハウリングで誤検出する。単独では信用できない。境界の±2秒微調整には有効。 |
| PySceneDetectでシーン分割 | ❌ 不採用 | 試合中もカメラは何度も切り替わる。1試合が10個に割れる。用途が違う。 |
| Whisperで全編文字起こしして判定 | △ 部分採用 | 4時間をCPUで回すと数時間かかる。しかもアナウンスは実際の開始より遅れる。**候補区間だけ**に限定して使うなら有効。 |
| OCRで選手名を取る | △ 保険として採用 | 装飾テロップの日本語OCRは誤読する。**対戦表を3分で手入力するほうが100%正確で速い**。OCRは「順番が合っているかの答え合わせ」に使う。 |
| Gemini API無料枠で動画を解析 | ❌ 依存禁止 | 無料枠の条件は将来変わる。4時間動画は投げられない。**外部APIが死んでも全機能が動く**設計にする。文章生成の「あれば嬉しい」枠に限定。 |

**採用する主判定：スコアボードのテンプレート照合（OpenCV相当の処理をnumpyだけで実装）。**

## 2. もう1つの重要な設計判断：「解析」と「書き出し」を切り離す

自動化システムが数年もたない最大の理由は、**間違えたときに人間が直せない**ことです。

そこで、処理を必ず2段階に分けます。

```
解析  → segments.json（人間が読める・直せる中間ファイル）→  書き出し
```

- 検出が90点でも、**残り10点を手で直せば100点**になります（1大会あたり2〜3分）。
- 直した区間には `"locked": true` が付き、**再検出しても人間の修正は絶対に上書きされません**。
- この JSON はそのまま「次回の精度改善のための教師データ」になります。

「全自動で完璧」を狙うと壊れます。**「95%自動＋2分の確認」が、100回の大会を回せる唯一の形**です。

## 3. システム構成図

```
┌──────────────────────────────────────────────────────────────┐
│  入力：YouTube URL（＋ 対戦表 card.yml：任意）                  │
└──────────────────────────────┬───────────────────────────────┘
                               │
                     ┌─────────▼─────────┐
                     │ 1. download       │  yt-dlp（無劣化DL）
                     │    source.mp4     │  ※1回だけ。再実行はスキップ
                     └─────────┬─────────┘
                               │
                     ┌─────────▼─────────┐
                     │ 2. probe          │  ffprobe
                     │  尺・キーフレーム   │  → keyframes.json（キャッシュ）
                     └─────────┬─────────┘
                               │
        ┌──────────────────────▼──────────────────────┐
        │ 3. score（主判定）                            │
        │  ffmpeg で 1fps・ROI（スコアボード枠）だけを    │
        │  グレースケール切り出し → テンプレートとZNCC照合 │
        │  → scores.json（1秒ごとの一致度 0.0〜1.0）     │
        └──────────────────────┬──────────────────────┘
                               │
        ┌──────────────────────▼──────────────────────┐
        │ 4. segment（状態機械・純ロジック）             │
        │  ヒステリシス → 短すぎ除去 → 隙間ブリッジ       │
        │  → 前後のり付け → 重なり解消                   │
        └──────────────────────┬──────────────────────┘
                               │
                     ┌─────────▼─────────┐
                     │  segments.json    │◀── ★人間がここで2分確認・修正
                     │  （中間成果物）     │    locked:true は次回も守られる
                     └─────────┬─────────┘
                               │
        ┌──────────────────────▼──────────────────────┐
        │ 5. render                                    │
        │  ffmpeg -c copy（再エンコードなし＝無劣化）     │
        │  キーフレームに吸着して切る                     │
        └──────────────────────┬──────────────────────┘
                               │
                  out/第13回大会/01_赤選手vs青選手.mp4
                                 02_….mp4

──────────── ここまでが MVP（今回実装） ────────────
──────────── ここから先は段階追加（承認後） ────────────

  STEP2  audio  : ゴング音で開始位置を±2秒補正（librosa）
  STEP2  names  : card.yml（対戦表）で選手名を確定 ＋ OCRで答え合わせ
  STEP3  captions: YouTube/TikTok/Instagram/X の投稿文をテンプレ生成
                   （Gemini無料枠 or ローカルLLMは「あれば使う」任意プラグイン）
  STEP4  vertical: 9:16 黒帯変換（必要になったときだけ）
```

**設計の肝：`segment.py` `naming.py` `timecode.py` `manifest.py` と `render.plan_cut()` は
ffmpegもnumpyも使わない純ロジック**です。だから CI でも手元でも1秒でテストできます。
壊れやすい外部コマンド呼び出しは、薄い層に閉じ込めています。

## 5. 処理フロー（実際のコマンド）

### 初回だけ（1シリーズにつき1回・約10分）

```bash
# 1) 大会動画を落とす
python -m uizin_clipper download "https://www.youtube.com/live/XXXX"

# 2) 5分おきの静止画を出して、スコアボードの位置を目で確認する
python -m uizin_clipper contact-sheet --video work/XXXX/source.mp4

# 3) 「試合中の1枚」とスコアボードの枠を指定して基準画像を作る
python -m uizin_clipper calibrate \
    --video work/XXXX/source.mp4 \
    --at 00:23:10 --roi 1180,55,620,130 \
    --profile profiles/uizin.yml
```

### 2回目以降（毎回これだけ）

```bash
python -m uizin_clipper run "https://www.youtube.com/live/YYYY" \
    --profile profiles/uizin.yml \
    --event "第14回大会"
```

内部では `download → probe → score → segment → (確認) → render` が順に走ります。
**各ステップは中間ファイルを見て「もうある」と判断したらスキップ**します（冪等・再開可能）。
4時間動画のダウンロードや解析を、失敗のたびにやり直す必要はありません。

### 確認して直す（2分）

```bash
python -m uizin_clipper list --manifest work/YYYY/segments.json
#  01  00:12:04 → 00:18:33  (6:29)  conf 0.94
#  02  00:21:40 → 00:27:02  (5:22)  conf 0.91
#  03  00:31:12 → 00:33:05  (1:53)  conf 0.58  ← 低い。ここだけ目視

# segments.json を直接編集し、直した区間に "locked": true を付ける
python -m uizin_clipper render --manifest work/YYYY/segments.json --event "第14回大会"
```

## 6. 採用理由

| 技術 | 役割 | 採用理由 |
|---|---|---|
| **yt-dlp** | 取得 | 無料・OSS・YouTube仕様変更への追従が最速。無劣化のまま取得できる。 |
| **FFmpeg** | 解析入力／書き出し | 無料・どこでも動く・**`-c copy` で再エンコードなし＝画質劣化ゼロ**。フレーム抽出も同じ1本で済む（依存を増やさない）。 |
| **numpy（ZNCC照合）** | 主判定 | 「明るさが変わっても形が一致すれば当たる」正規化相関。OpenCVすら不要でnumpy 20行。**依存が少ないほど数年後も動く**。 |
| **状態機械＋ヒステリシス** | 区間化 | しきい値1本だとテロップの点滅で区間がバラける。入口0.62／出口0.45と差をつけ、隙間はブリッジして1試合にまとめる。 |
| **キーフレーム吸着カット** | 書き出し | `-c copy` はキーフレームでしか切れない。**手前のキーフレームに吸着**させれば劣化ゼロのまま、余った分は「入場の余韻」として自然に使える。 |
| **中間JSON＋locked** | 保守 | 人間の修正が消えない。これが100回運用できるかの分かれ目。 |
| **プロファイルYAML** | 拡張 | 第20回でテロップデザインが変わっても、**触るのは設定ファイル1枚だけ。コードは変更しない**。 |
| **対戦表 card.yml** | 選手名 | 3分の手入力で100%正確。OCRの誤読リスクをゼロにできる。 |

---

## 7. 不採用理由

| 不採用 | 理由 |
|---|---|
| YOLO等の物体検出で選手を認識 | アノテーション作業が発生・GPU前提・大会ごとに再学習。無料と保守性に反する。 |
| PySceneDetect を主判定に | 試合中のカメラ切替で1試合が細切れになる。**補助にも使わない**（ROI照合のほうが上位互換）。 |
| Whisper 全編文字起こしを主判定に | CPUで4時間分＝数時間。アナウンスは実際の開始から数秒〜十数秒ずれる。STEP2で候補区間だけに使う。 |
| Gemini API に動画そのものを投げる | 無料枠の制限・将来の条件変更・再現性なし。**外部APIが止まったら全部止まる**構成は禁止。 |
| クラウド常時稼働（Lambda/GPUサーバ） | 月額が発生する。絶対条件（毎月課金禁止）に違反。**手元のPCで実行が最安**。 |
| 再エンコードして秒単位で正確に切る | 画質劣化＋4時間分のエンコード時間。既定は無劣化。必要なときだけ `--precise` を将来追加。 |
| 縦動画（9:16）の自動生成 | 現時点で不要と明言されている。作らない。必要になったら黒帯変換を1コマンド追加するだけ。 |
| GUI／Webアプリ化 | 保守対象が増える。CLI＋JSONが最も壊れにくく、将来 openQLOW から呼ぶのも容易。 |

## 9. 制約・注意点（正直に書く部分）

1. **初回のキャリブレーションは人間が必要**です（約10分）。スコアボードの位置と見た目を
   システムは知らないためです。2回目以降は不要で、テロップデザインが変わるまで使い回せます。
2. **キーフレーム吸着により、開始が最大数秒だけ手前にずれます**。無劣化と引き換えの仕様で、
   前のりしろとして実用上は有利に働きます。厳密に必要なら再エンコード版を後から追加します。
3. **本設計は実配信の映像を未確認のまま立てています**。ROI座標・しきい値の初期値は
   キャリブレーションで実測に置き換わる前提で、暫定値です（推測であることを明記します）。
4. **著作権・肖像権**：切り抜き公開の可否、選手・観客の映り込み、BGMの権利は
   システムの判断範囲外です。公開はオーナー承認後に行ってください。
5. 大会動画そのもの・生成物・対戦表は **Gitにコミットしません**（`.gitignore` 済み）。

## 10. 実測でわかったこと（2026-08-07 追記）

第13回大会の実配信は、この作業環境の**エグレスポリシーで YouTube が遮断**されているため
取得できませんでした（`youtube.com` / `googlevideo.com` ともに CONNECT 403）。
実配信での検証は**未完了**です。

代わりに、疑われていた失敗モードを再現できる検証用動画を作り、
**アルゴリズム側の性質だけ**を実測しました。以下は合成映像での測定値であり、
実配信の精度を保証するものではありません。

検証用動画の条件（実配信で問題になりそうな要素を意図的に入れた）:

- 背景が常に動く（カメラ切り替え相当）
- スコアボードの**中身が変化する**：タイマーの桁が毎秒変わる、得点が増減する
- **試合ごとに選手名テロップの長さが変わる**（試合Bは行が1つ多い）
- 圧縮ノイズあり（CRF 32 で再エンコード）
- ラウンド間の途切れ（20秒・25秒）と、試合間の休憩（80秒）

### 10.1 ROIの選び方が精度を決める

基準画像は「試合A・1R」から取得。1秒ごとに ZNCC を測定（各 219 サンプル）。

| ROI | 試合A（基準の元） | 試合B（名前の長さが違う） | 試合外 |
|---|---|---|---|
| スコアボード全体 | 中央 0.945 | 中央 **0.856** | 最大 0.360 |
| 枠とロゴだけ | 中央 0.994 | 中央 **0.993** | 最大 0.000 |

**スコアボード全体を囲むと、選手名が変わるだけで一致度が 0.09 落ちます。**
枠とロゴだけに絞ると落ちません。

→ **判定用ROIは「試合中ずっと変わらない部分」だけにする**。
   AI に逃げる必要はなく、囲む場所を変えるだけで解決します。

### 10.2 秒数だけでラウンドを繋ぐのは無理

同じ動画に対し `max_gap_sec` だけを変えた結果（正解は2試合）:

| max_gap_sec | 検出 | 判定 |
|---|---|---|
| 20秒 | 3本 | 1試合が2本に**分割** |
| 30秒・60秒 | 2本 | 正解 |
| 90秒 | 1本 | 2試合が1本に**結合** |

正解になる窓は存在しますが、それは「ラウンド間 < しきい値 < 試合間」が
たまたま成り立っているだけです。実配信でこの関係が崩れれば必ず破綻します。

### 10.3 採用した最小構成：テロップが同じかで判断する

秒数をやめ、**途切れの直前と直後で選手名テロップを照合**します。

| 同一試合判定ROI | 試合A内(20秒) | 試合B内(25秒) | 試合A→B(80秒) | 判定 |
|---|---|---|---|---|
| 名前だけ | **1.000** | **1.000** | **0.770** | ◎ 余裕をもって分離 |
| 名前＋タイマー | 1.000 | 0.781 | 0.514 | ✕ 同じ試合が割れる |
| スコアボード全体 | 0.959 | 0.980 | 0.867 | △ 余裕が 0.09 しかない |

**タイマーを含めてはいけない**ことが数値で出ました。

この方式にしたあと、`max_gap_sec` を 5秒 / 20秒 / 30秒 のどれにしても
検出結果は **2本で一定** になりました。しきい値の当てずっぽうが不要になります。

判断の根拠は実行ログにそのまま出ます。

```
[round] 途切れ 20秒: テロップ一致度 1.000 → 同じ試合（繋ぐ）
[round] 途切れ 80秒: テロップ一致度 0.770 → 別の試合（繋がない）
```

使うのは主判定と同じ ZNCC だけです。**無料・CPU・説明可能**の条件は維持しています。

### 10.4 無地ROIによる無言の失敗を塞いだ

模様のない場所（真っ白な帯など）を ROI に選ぶと ZNCC は常に 0 になり、
「1件も検出されない」という結果だけが出て理由が分かりませんでした。
基準画像のばらつきを検査し、**calibrate で警告・detect で理由を出して停止**するようにしました。

### 10.5 実配信で確認すべきこと（未実施）

以下は実配信でしか確かめられません。オーナー環境での実行が必要です。

1. UIZIN のスコアボードに「ずっと変わらない部分」が実在するか（枠・ロゴ）
2. ラウンド間にスコアボードが消えるのか、出たままなのか
3. MC・入場・休憩・表彰・リプレイ・選手紹介を誤検出しないか
4. 実際の試合数と検出数の一致（`report --truth` で数値化する）
5. 出力MP4の品質（`report --out-dir` で機械的に点検する）
