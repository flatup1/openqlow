## 3. 仕組み（3分で分かる技術）

場所は `girl-power-op/`。AIサービスに依存せず、**ローカル計算だけ**で動く。

```
絵（scenes/*.jpg） ＋ 物語（story.ep0X.js）
        ↓  index.html の draw(t) が「t秒の絵」を描く
        ↓  render.js が Playwright で1/30秒ごとに撮影
        ↓  ffmpeg で BGM と合わせて MP4
     完成（flatup_ep01.mp4 など）
```

**設計上の要点:**

| 要点 | なぜそうしたか |
|---|---|
| `draw(t)` は**時刻だけの純粋関数** | タイマーを使わないので、状態のズレ・リセット漏れのバグが構造的に起きない |
| 物語は**データファイルに分離** | プログラムを触らずに物語だけ書き換えられる |
| BGMは**Web Audioで自前合成** | 著作権フリー。静かなシーンでは自動でオルゴール風に切り替わる |
| 絵の読み込みは**1枚ずつ try/catch** | 絵が1枚無くても再生が止まらない |

**動かし方:**

```bash
cd girl-power-op
npm install                       # 初回のみ
npx playwright install chromium   # 初回のみ

# ブラウザで確認
#   index.html?story=ep01   第1話（少年編）
#   index.html?story=ep02   第2話（少女編）
#   index.html?story=op     旧デモ版
#   （指定なし）             story.flatup.js（サイト埋め込み用の短い版）

# MP4に書き出す
node render.js --story=ep01              # → flatup_ep01.mp4（横型 1280x720）
node render.js --story=ep01 --vertical   # → flatup_ep01_vertical.mp4（1080x1920）
```

ffmpeg はこの環境では次の場所にある（`FFMPEG` 環境変数で指定）:

```
/usr/local/lib/python3.11/dist-packages/imageio_ffmpeg/binaries/ffmpeg-linux-x86_64-v7.0.2
```

**注意:** `?loop=1` を付けると連続再生モードになり `seek()` が効かない。
フレーム撮影のときは `loop=1` を付けないこと。
